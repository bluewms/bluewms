# ERP 接口管理 /1

在“设置”顶部点击“技术”右侧的“ERP 接口管理”进入业务接口列表；列表顶部保留 ERP 连接、关联单据、同步记录与外部操作按钮。新建 ERP 连接，再在业务接口中创建入库、出库、内部调拨或盘点差异接口。每个接口共用 AI 草稿／试算／不可变版本／人工发布／回滚流程，对应既有“ERP接口”Task，合同为 `erp_mapping/1`。

- ERP 推送到 `/blue_erp/v1/interfaces/<接口编号>/documents`，使用该接口的 Bearer 接收凭据。单头由代码解析；配置的顶层明细数组作为 candidates。固定服务以人工指定执行用户和公司建单，保留库存权限及原生预留／上架流程。
- 固定服务接受代码输出的商品编码、库存单位、已有批次、允许范围内的库位，以及分组键。同一分组创建一张 WMS 库存单；ERP 单头与每行 ID 使用文本，支持原生欠单。
- 重复单据内容相同返回原结果；变化内容拒绝并要求人工核对。本版不自动修改／取消已有 ERP 来源单据，也不自动创建商品、单位、往来单位或批次。
- 库存单实际验证完成才记录事件；部分完成按本次实际数量反馈，累计不得超过原计划。每张原单或欠单各有稳定事件键，使用来源固定版本。
- 盘点接口明确选择同步内部库位，发布后接入原生库存调整。差异为零不发送；调整前账存／实盘／批次／包裹／货主及差异保存为不可变快照。代码可拆为盘盈、盘亏操作。
- 代码仅引用人工批准的操作代码，固定服务通过对应路径进行 HTTP(S) JSON POST。多个操作按顺序执行，成功步骤不再发送。`Idempotency-Key` 由服务生成，ERP 仍需实际支持去重；HTTP 超时／发送中断转待核对。
- 同步记录和外部操作页支持查看准确报文、固定版本、状态与处理历史。只有库存管理员明确核对并填写说明后，才能确认成功或确认未处理后重新排队。库存完成不等待网络调用。

## 部署与验证

依赖 `blue_stock_rules`、`blue_config_asset`、`blue_ai_client` 和共享执行合同，独立于 WCS。先在隔离 `*_test` 库安装并回归，再备份主库数据库和 filestore，核对库存／资产／人工配置后安装。本模块不会安装客户案例或自动发布策略。

知识来源在 [ERP Wiki](https://gitee.com/jch100322/bluewms-wiki/blob/master/wiki/domains/erp/specification.md)。云端必须单独部署 ERP 合同白名单并发布批准的规范／准确案例；未批准时 AI 工具保持拒绝生成，不使用本地示例兜底。人工可维护代码并试算发布。

第一版范围是 ERP 主动推送、单次 JSON HTTP 操作和响应解释；轮询／分页拉单、金蝶 SDK、动态 Token 获取、前一步响应给后一步补字段、自动单据变更／取消仍待扩展。旧 E10／金蝶协议是参考，不代表本版本已完成其认证或现场联调。
