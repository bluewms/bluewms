# 宝蓝 AI 云端连接

`blue_ai_client` 独立扩展 MuK AI，提供 Chat Completions、每用户云端身份和上架代码草稿工具，不修改 MuK 上游核心。

## 设置与入口

MuK AI → 设置 → 宝蓝云端服务：启用连接、填写服务地址及模型。配置 → 宝蓝用户连接：管理员为每个内部用户填写自己的业务用户 API Key 和准确 Agent 名称。

- 团队固定 `odooAI`；新上架会话进入“上架策略”Task。普通聊天、测试连接及升级前的旧会话继续使用“日常任务”。
- 默认模型入口 `https://odooapi.royalblue56.com/codebuddy/default`，自动补齐 `/v1/chat/completions`；也接受完整端点。Skill 桥接使用同一配置地址的 origin 下 `/skill-bridge/v3/skill/*`，反向代理须提供该路径。
- 默认模型 `glm-5.3-Flash`，每次输出上限 8192；首次安装 provider 禁用，不写入真实 Key。测试连接会产生一次模型调用。
- Key 字段仅管理员读取；运行时只取当前 Odoo 用户的连接。没有连接时直接报错，不借用管理员凭据。
- 不维护充值／扣费账本或剩余额度；MuK token／费用统计不能代替云端实际扣费。

库存 → 配置 → 上架策略，填写名称、选择“上架增强接口 v2”，然后点击“AI 生成 / 修改”。已有场景保留原接口，不需要换模板。当前 AI 入口只开放上架；其他四类的业务合同与工具还需分别接入。

AI 生成／修改默认在当前页面打开 MuK 聊天浮窗，保留上架策略表单和地址。代码会话的浮窗为约 437 × 644 px（较原浮窗宽、高增加 15%），受屏幕可用空间限制；标题栏可放大／恢复、最小化或关闭，放大仍留在当前业务页面。普通 MuK 会话保留原有尺寸和全屏页面入口。

## 生成与知识读取

MuK 主持工具循环。业务用户 Key 仅用于认证头，云端代理根据初始化表单准确匹配团队、Agent 和 Task，不让模型猜身份。会话绑定资产、合同、公司、草稿摘要及正式基础版本；身份变化或资产冲突时要求重新从资产页面打开。

三个专用工具：

1. `blue_read_code_asset` 返回当前草稿、测试、需求、版本摘要、完整 `contract_schema`，并实际读取云端批准知识。它不返回 `example_code`／`example_tests`。
2. `blue_submit_code_draft` 检查并发与基础版本，必须已有成功知识读取，保存 AI 草稿及准确参考资料的版本／摘要。
3. `blue_validate_code_draft` 执行本地受限解释器与测试，反馈错误用于修复；不发布。

知识读取通过代理的 Skill bridge：先用固定名称 `bluewms-policy-authoring` 搜索，执行代理当前身份的可见性检查，再读取唯一匹配的 active、`metadata.approved=true`、`purpose=odoo_runtime_policy` 版本及三个固定非执行资源：项目治理、合同参考、批准上架示例。它们与团队 Wiki 的维护来源一致；本轮不是直接调用任意 Wiki 搜索。

模型不能指定 URL、身份、Skill ID、文件路径或命令。单次响应上限 128 KiB、总知识正文 32 KiB、整体读取预算 30 秒，拒绝重定向，错误不回显服务正文。会话首次读取后固定版本及 SHA-256，再次读取不接受静默漂移。读取失败不会回退到本地通用示例，也不会自动改草稿。

完整合同由已安装的本地解释器和上架接口定义：字段、类型、允许语法、唯一 `result.append` 调用、资源边界、测试格式及“系统优先”约束。云端示例不能覆盖本地合同。受限会话不提供通用 ORM、文件、shell 或发布工具，也不注入 MuK 通用文件／Skill 工具说明。

## 本地保存和升级

本地仍保存当前／正式代码、本次试算用例、不可变版本、发布回滚和执行记录。批准知识只记录来源、版本与摘要，不建立客户本地示例库。已发布版本无需云端在线即可执行或回滚。

升级保留原模板 ID、合同及批次能力标记，退役原系统示例选择；仅清理与原出厂摘要完全一致的通用示例正文。管理员修改的旧示例内容保留待人工处理；不回传给 AI。WCS 原有手动示例流程不在本轮改造范围。

具体升级、验证与限制见 [上架云端知识接入交付](../docs/migrations/putaway-cloud-knowledge-20.md)。
