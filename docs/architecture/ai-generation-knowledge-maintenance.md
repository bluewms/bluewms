# Odoo AI 生成知识的维护与发布（维护者资料）

更新：2026-10-18。本文供人工维护者使用，不发布到 Odoo AI 代码生成 Wiki。生成资料位于 [docs/wiki/](../wiki/README.md)，其读者是 Odoo 内的宝蓝代码助手。

2026-10-18 接入规划：目标为一个通用规则库加五个业务 Wiki，使用腾讯标准搜索／读页工具，逐步替代额外 Skill 正文副本。六库现已发布 29 份准确资料并完成逐页读回核对；正式 Odoo 页面内的新检索工具尚未切换。详见[本轮发布验收](../wiki-publication/native-wiki-20261018.md)。本文下述固定资源是当前兼容实现，不是新的最终架构；详见 [原生检索规划](native-wiki-retrieval-plan.md)。

## 文件职责

- `docs/wiki/basics/`：给 Odoo 助手使用的生成通用规则和工具步骤，不含工程、Git 或服务器配置。
- `domains/<领域>/specification.md`：该类合同、能力边界和生成规范，不能把规划接口写成已开放。
- `domains/<领域>/examples/`：一个案例一个文件，保留准确代码、试算输入、期望和验证证据；`README.md` 作案例目录。
- 配置、安装、联调与历史放在 `docs/architecture/`、`docs/third-party/`、`docs/migrations/`；不得作为生成知识正文发布。
- `ai-generation-knowledge-publication-map.json`：保留旧 Skill 兼容映射，不是新 Wiki 发布器；原生分库以 `native-wiki-knowledge-registry.plan.json` 和实际发布清单为准。

## 状态分别记录

| 知识状态 | 含义 | 能否作为已验证可执行示例 |
|---|---|---|
| `planned` | 设计／需求样例，合同或 AI 入口尚未具备 | 不能 |
| `draft` | 文稿或代码候选，验证／审阅未完成 | 不能 |
| `verified` | 指定版本下的准确代码和测试已验证，证据齐全 | 还需按云端批准流程发布 |
| `deprecated` | 已失效或被替代，保留原因及替代链接 | 新生成不再选用 |
| `historical` | 某个日期的证据，不能覆盖当前规范 | 仅作追溯 |

文档状态、业务实现状态、云端批准／发布状态是三件事。`verified` 不是自动给云端写入 `approved=true`，Git 合并也不会自动更新 Wiki／Skill。本轮来源提交 `5770f8a` 已发布到六个 Wiki；当前 Odoo 页面内工具仍读取旧 Skill。索引可读与运行工具切换分别验收。

## 新增一个案例

1. 复制 [示例模板](../wiki/templates/example-template.md)，保存到对应领域的 `examples/<稳定名称>.md`；不要把新案例追加到综合配置说明里。
2. 写明稳定知识 ID、hook、合同／模块版本、需求、适用范围、限制、准确代码、测试和预期。示例 ID 不使用某台数据库的记录 ID。
3. 用同版本受限解释器验证所有声明的用例；涉及业务约束时补真实业务回归。纯代码试算通过不能证明托盘容量、公司权限或设备动作正确。
4. 记录日期、来源提交／交付记录和结果，在该类示例目录添加链接。现有测试 fixtures 是固定回归证据，不能把修改文稿当作已经同步测试。
5. 通过任务分支和 PR 审阅。`main` 受保护，不直接推送或强推覆盖。

规范变化先更新该类规范，并确认本地合同是否也需正式模块变更；只有文档变化不能开放新字段、语法或动作。

## 发布到云端

生成规范和案例的人工编辑来源在 `docs/wiki/`；云端是 Odoo AI 使用的批准发布版本。本文、服务器配置和历史不属于生成知识。云端新增经验先作候选，审阅后回写来源、验证，再正式发布，避免两套正文长期分叉。

按[分库清单](native-wiki-knowledge-registry.plan.json)和[实际发布摘要](../wiki-publication/native-wiki-20261018.manifest.json)选择来源。使用标准 page/write 逐页写入带来源、合同、状态与摘要的锁定正文，再建立标准索引并读回核对。代码及完整测试不交给 LLM 摘写；工程背景、配置、历史均留在 Wiki 之外。后三类 planned 资料单独存放，不能标记为已批准可执行案例。

旧上架客户端依赖三个固定资源，旧 WCS 分支还要求独立 06／07（现未补写）。未同时升级并验证客户端前，不删除或改名这些资源；重组文档不等于修改运行时路径。示例资源仅收录 `verified` 案例，ERP／设备／条码三个 `planned` 领域不得混入批准上架／WCS 示例。

记录发布清单：来源提交、所含知识 ID／合同版本、正文摘要、云端资源 ID／版本／批准状态、操作者和日期。公共 Git 只放非敏感证据，凭据与原始回执留私有记录。用业务用户验证正文、共享和隔离，新会话确认版本；Wiki 没有已验证的历史版本读页参数；新原生会话须冻结真实版本与摘要，来源漂移时拒绝继续提交，不声称可自动读取旧页。已冻结的本地代码版本保持原记录。

发布前有备份，发布失败不替换批准正文；失效知识保留替代关系，不能追溯修改已经冻结的本地代码版本。当前 32 KiB 上限计算整个 bundle 的 UTF-8 JSON 字节，含 Skill 主文、三个资源正文和包装字段，不能只统计代码。接近限制时先调整检索／资源方案并完成客户端验证，不直接扩充到运行工具无法加载。

## 修改原有说明或配置

生成规则更新 `docs/wiki/basics/`；实际服务器变更只记录在工程文档，写明日期、旧值／新值和验收。旧记录加替代链接，不把历史健康检查、测试或版本号改写成今天刚完成。引用其他页面时使用相对路径，不复制第二份同名规范。
