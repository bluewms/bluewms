# AI 知识维护与发布

更新：2026-10-18。本文供维护者使用，不上传到生成 Wiki。**唯一维护来源是 `docs/wiki/`**；运行时使用腾讯原生 Wiki，不另维护综合知识稿、Skill 正文副本或客户本地示例库。

## 文件和状态

`basics/` 保存通用生成规则与工具步骤；`domains/<领域>/specification.md` 保存规范；`examples/` 一个案例一页，保留完整代码／输入／期望、限制及来源。`templates/` 只提供案例格式，不是已验证可执行案例。工程、Git、安装、配置和排错历史留在其他目录。

| 知识状态 | 含义 |
|---|---|
| planned | 合同或能力尚未开放，只能讨论需求 |
| draft | 文稿／代码候选，尚未完成验证及审阅 |
| verified | 同版本代码与声明用例已验证，仍需平台批准及发布 |
| deprecated | 不再用于新生成，记录替代知识与原因 |

文稿 verified、Wiki 索引 ready、平台资产 approved、代码草稿验证和正式策略发布分别记录。Git 提交／合并不自动改变云端，也不能把旧测试当成本轮执行结果。

## 新增或修改案例

1. 从[模板](../wiki/templates/example-template.md)建立独立文件，填写稳定知识 ID、hook、适用合同、需求、范围、前提、边界和来源。
2. 使用当前真实合同，不发明字段、方法或执行能力。planned 文稿不提供看似可执行的代码／schema。
3. 已实现案例保留准确完整代码、输入／期望；用同版本解释器验证，涉及业务约束时补模块或真实作业回归。上架使用 expected_order，WCS /4 使用 expected_result 并覆盖 lines/tasks。
4. 更新本领域目录，记录来源提交与实际验证证据，保留许可证／作者；通过任务分支和 PR 审阅。

统一校验入口为 `scripts/validate_ai_wiki.py`，目前覆盖三个上架＋十个 WCS 案例共 34 条声明试算、/4 合同附件与 Wiki 链接，仅允许隔离 `*_test` 库。增加案例时同步维护 fixtures 和该校验入口，不恢复已删除的旧综合稿校验器。

## 发布步骤

1. 按[六库逻辑清单](native-wiki-knowledge-registry.json)确定目标。实例 ID 和服务凭据只存私有部署配置。
2. 备份知识／元数据数据库及准确目录，检查归档内容；记录现有来源、版本、批准状态、正文摘要和绑定。
3. 通过标准 `wiki/page/write` 逐页写入准确正文和来源元数据，锁定代码／测试页；合同 JSON 作为完整核对附件，不用 LLM 摘要替代。
4. 保留准确来源快照并建立标准索引。现有版本的 ingest 要求 raw 来源；本轮采用 `source-snapshot.json` 及已审阅页面建立索引，避免把代码再交给 LLM 重写，见[发布证据](../wiki-publication/README.md)。
5. 使用标准 tools/list、search、read_page 验证 ready，并将全部正文与预期摘要逐页核对；再更新平台用途、合同、批准页清单和版本。planned 领域保持 candidate／generation_ready=false。
6. 用不同成员的业务 Key 验证绑定、ACL、搜索和完整读页；真实模型测试必须实际调用工具并引用正文，不能把预先塞入答案视为检索成功。
7. 新会话核对真实 Task、合同与来源；保存回执、来源提交、页摘要、操作者、日期及测试结论。公开证据脱敏，秘密、实际实例 ID 和原始记录留私有目录。

现有只读通道使用原生标准工具，来源为 tencent_wiki。旧 Skill 资源只为尚未升级的客户端保留，不再作为新发布目标；不要为满足旧资源路径把整套 Wiki 再复制一次。

## 版本与恢复

Wiki 没有已验证的“按历史版本读页”参数。新会话冻结实际 Wiki／资产版本、批准来源和正文摘要；变化后中止或重开，不静默改读新版或使用本地副本。恢复依靠准确来源提交、批准包和备份，不从聊天摘要重建代码。

Odoo 对读页数量、单次响应、累计正文和超时有边界，具体值见[当前接入](../migrations/native-wiki-runtime-20.md)与代码。超量时选择较少完整案例，不截断代码／测试。云端知识库容量不能与旧 32 KiB Skill bundle 限制混为一谈。

发布清单记录的是指定提交的准确来源。如果改动已发布的 `docs/wiki/`，其摘要应变化并按上述流程重新发布；单纯整理工程目录不应重写 Wiki 来源或虚增云端版本。
