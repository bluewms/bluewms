# 19 版前端操作能力补充

日期: 2026-10-23. 在 [16 版终端交互](barcode-16-terminal.md) 上补充 19 版操作语义,当前仅在 8071 隔离库安装. 来源摘要见 [来源锁](barcode-source-lock.json).

| 19 版入口 | 本轮行为 |
|---|---|
| canBeValidate / highlightValidateButton / validate | 未录入有效数量时禁用,服务端同时拒绝预留冒充已扫;完整时显示主色整单验证,部分时显示已扫数量验证;待补追踪必须先完成或明确取消 |
| BackorderDialog / create_backorder | 验证前逐项显示单据、产品、需求、已扫、剩余和 ask/always/never;按实际 move 汇总需求,不重复统计拆开的行;继续原生欠单及其他预检向导,不跳过原生数量/追踪/WCS/库存检查 |
| _closeValidate / history-back | 原生向导关闭后重新读取真实状态;需要时重新建立固定会话;完成页提供欠单和仍未完成的原作业. 完成页刷新可保留,普通释放的未完成会话不误显示完成 |
| 批次 action_done | 整批复核,保留单据归属. 未扫成员不当成完成,原生流程移出旧批次并保留单据;启用自动组批时允许原生分配新批次 |
| 装箱 / canPutInPack | 仅本页已确认且未装箱的明细可点;确认后使用原生装箱和原生返回向导,装完禁用. 不跨页顺带装其他组 |
| WCS validate patch | WCS 作业优先显示执行 WCS;已完成 WCS 时可回到库存验证. 必需 WCS 未完成时界面和服务端均阻止直接验证;仅有确认数量的批次成员交给正式入口,不接收任意 move line ID,不重加数量 |
| actionsView / 打印 | 右上角操作与打印: 原生单据、拣货作业单、送货单、批次作业单、产品/批次标签、包裹标签. 使用固定白名单,按权限显示,先核对前序输入;不从 PDA 修改公司报表版式 |
| cancel | 人工确认后走原生取消;现有 WCS 取消约束继续生效. 取消批次只解散关系,不取消原库存作业. AI after 不能请求 cancel |
| returnProducts | 完成且原生允许退回时出现退货入口. Odoo 20 使用原生完成单据上的退回操作: PDA 更多菜单/桌面按钮;打开只导航,不自动创建或记账. 本轮没有复制 19 版已退役的退货向导 |
| 纸面操作码 | OBTVALI 触发当前验证/WCS 主按钮及确认;OBTPACK 装箱;OBTPROP/OBTPRSL 打印;OCDCANC 人工确认取消;OCDMENU 返回首页;OBTRETU 进入允许的原生退货. 只匹配完整固定码,不执行任意方法 |

商品和完整 QR 继续使用原生 barcode_scanned 总线. PDA 采集先处理固定操作码,避免 Odoo 全局 OCD 处理器把终端命令再判为未知. 相机结果进入同一固定处理函数. 操作页仅接受操作码,商品需回到作业页;请求/向导处理中不把新扫描混进验证中的数量,普通商品扫码的串行队列保持不变. 结束后只允许当前有效的单据操作,不再累计商品.

保留的范围: RFID/EPC 与报废仍按已确认计划后续迁移;独立签名页、包裹内容浏览及重新编组页面未整套复制,已有原生功能可由明确的查看单据入口使用. 临时加额外产品、改位置/所有者/批次等会改变库存维度的行为不借此开放,仍由正式单据/授权能力处理. 盘库继续先有盘库单,本轮没有把原生 quant 的整库盘点/应用按钮搬进来.

验证: 66 项后端、9 项采集通过. 浏览器验证未扫禁用、装箱、实际 PDF 下载、标签向导、部分完成和真实欠单、欠单跳转、完整验证、结果刷新、人工取消、结束后不计数、原生退货入口、WCS 按钮及操作码. 无真实设备命令/实机 PDA/相机验证. 版本、备份、日志和截图见 [进度记录](barcode-20-progress.md).
