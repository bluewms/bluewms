# 上架 AI 云端知识接入与本地接口调整

日期：2026-10-16。适用模块：`blue_ai_client 20.0.1.1.0`、`blue_config_asset 20.0.1.1.0`、`blue_extension_contract 20.0.1.4.0`、`blue_stock_putaway 20.0.1.4.0`。

## 生成方式

库存 → 配置 → 上架策略。新建场景默认选择“上架增强接口 v2”，写好需求并点击“AI 生成 / 修改”；已有场景沿用原接口，从页面新开会话。

1. 新会话绑定当前资产、公司、合同、草稿摘要和正式基础版本，准确选择当前用户 Agent 与“上架策略”Task。
2. 助手调用 `blue_read_code_asset`。本地返回当前代码、测试、完整机器可读合同，并通过云端 Skill bridge 实际取得批准正文。
3. 固定读取 `bluewms-policy-authoring` 的项目治理、合同参考和批准上架示例三个资源；先做可见性搜索，再核验 active、批准标记、用途、manifest 和版本。
4. 助手根据需求生成代码与本次测试，提交草稿，完成本地验证。知识来源、版本及 SHA-256 随代码版本保存。
5. 用户在资产页检查代码、试算／真实单据预览后发布。发布、执行及回滚仍由本地模块负责，不调用模型。

旧会话及普通聊天继续“日常任务”；新上架会话的代理标识包含用户、Key、Agent、Task、公司及合同范围。身份变化、公司／合同变化、手工编辑或正式版本变化后重新开会话。

## 本地保留和退役

`blue.scene.template` 保留 ID 与运行定义，不再把上架示例正文作为生成来源。新上架接口不包含示例代码和测试；原三个系统示例接口退出新建选择，已有资产的合同及批次要求不改变。

升级脚本只清理与原出厂 SHA-256 完全一致的说明、示例代码及示例测试。管理员修改过的内容保留作人工恢复材料，不传给 AI；不修改现有资产草稿、代码版本、发布快照或单据绑定。

本次试算输入和期望结果继续保存在资产内。`tests/data/putaway_regression_cases.json` 只用于自动回归，不属于 manifest 数据，也不会通过运行工具读取。WCS 既有手动示例流程保留，其他四类 AI 生成尚未开放。

## 边界与故障

- 模型不能传入任意 URL、路径、Skill ID、身份或命令。Skill bridge 使用当前模型服务同一 origin 的固定路径；反向代理须允许该路径。
- 云端知识单次响应 128 KiB、完整正文 32 KiB；读取预算 30 秒，逐请求连接／读取超时均有上限，不跟随重定向。
- 首次读取固定知识版本和正文／资源摘要；重复读取必须一致。来源失效、无权、超量、超时、缺资源或版本漂移均返回错误，不回退本地通用示例。
- 知识正文使用业务用户的代理会话读取，不把管理 Key、业务 Key 或 curl 命令放进模型工具结果。
- 当前使用批准 Skill 资源分发同源 Wiki 内容，没有开放任意 Wiki 查询、官方源码资源遍历或知识编辑工具。
- 固定项目 Skill 的后续批准版本可在新会话读取；当前会话维持首次版本。新增资源须维护 manifest／批准状态与客户端允许资源清单。
- 本地仍强制原生上架范围、优先级、重量、托盘数量、混放、冻结与公司权限。补充代码只能限制或排序；整托不拆分。

## 升级与验证

先备份 PostgreSQL，再在停止 Odoo 服务的维护窗口升级四个模块并启动：

```sh
docker compose -f docker/compose.yaml stop odoo
docker compose -f docker/compose.yaml run --rm --no-deps -T odoo \
  -c /etc/odoo/odoo.conf -d bluewms20 \
  -u blue_extension_contract,blue_config_asset,blue_stock_putaway,blue_ai_client \
  --stop-after-init --no-http --max-cron-threads=0
docker compose -f docker/compose.yaml start odoo
```

测试先在开发数据库的独立恢复副本执行，覆盖 AI 工具权限／并发、知识读取／批准／超量／重定向／版本固定、接口字段与真实输入一致性，以及上架和 WCS 回归。额外对比升级前后资产、不可变版本、发布、绑定、库存数量和库存明细的记录摘要，确保迁移不改业务数据。

本次独立恢复库联合测试 **150 项通过，0 失败、0 错误**。真实云端分别生成“同单集中”和“跨产品同批次号”草稿，前者 4 条、后者 6 条测试通过，额外独立输入校验也通过，均未发布。实际开发库升级后验证登录、资产表单和批准 Skill 版本 4 的正文读取正常，六类关键业务表摘要保持一致。详细记录见 PR 与私有运维日志。自动试算通过不代替现场业务验收；新策略仍须用户审核发布。
