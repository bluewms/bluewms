# WCS 使用与迁移边界

更新：2026-10-18。当前由 `blue_wcs_base`、`blue_wcs_extension`、`blue_wcs_wes` 与合同／资产模块组成。AI 新生成仅使用 `wcs_creation/4`；旧 /1–/3 的合同、固定计划和历史版本保留。

## 配置与操作

1. **WCS → 设备类别／设备**：人工填写厂商适配、连接、设备编码、任务类型及允许能力。凭据只在设备配置中管理，不交给 AI。
2. **库存 → 配置 → 作业类型 → WCS**：明确方向、设备类别、主设备及任务类型；附加设备、交接点、自动创建、自动验证和验证必须有 WCS 由人工授权。
3. 不绑定 AI 创建配置时，每条正数量就绪行按实际起终点创建基础 goods 任务。无需模型、Wiki 或策略发布；同一整载具多行不能逐行重复搬运，须采用完整组合或实际拆开载具。
4. **WCS → AI 创建配置**：新建 /4 资产，人工编辑或从资产页打开 AI 浮窗；试算显示行决定、商品／数量、物理点位、任务及依赖。验证和真实作业预览后人工发布／绑定，不能由 AI 开启自动开关。
5. 从库存作业执行 WCS，查看计划、任务和回执。所有必要步骤完成并通过数量、覆盖与库存校验后，才按原开关执行库存验证。

上架与 WCS 共用浮窗，但 WCS 使用自己的 **WCS生成策略** Task、合同和 Wiki，不读取上架案例。独立知识讨论可从 **MuK AI → 宝蓝业务知识 → WCS生成策略** 进入，不能在无绑定资产的讨论中提交代码。

## 当前 /4 行为

全部有效行进入 `lines`，每行明确 `create`／`wait`／`exclude`、数量依据／数量、组合和物理位置来源。固定服务复核后在 `tasks` 阶段为就绪组编排 0–4 个步骤。

- 同数据连续程序用 `repeat`；连续路线接力用 `relay`。后续 goods 必须等待上一 goods 的 `end`，不能靠 point／take 作为已经完成。
- 一个物理计划只保存一份货物数量。多张任务各有独立身份，重复点击／扫描／并发按覆盖量和载具锁防重，库存最终只记一次。
- 行确认、载具全部确认、整单全部确认和显式满载阈值分开；最大运输重量不能作为最小满载标准。重量基础数据缺失时应等待。
- 实际库存／预留、整载具货物完整、公司／冻结及人工设备授权在规划及发送前复核。等待行不能通过遗漏或排除豁免绕过。
- 物理任务映射不修改原库存记账位置。回报未计划的实际细点时暂停核对，不自动改写库存。

设计取舍与验收不变量见[编排设计](../design/wcs-v4-orchestration.md)。完整字段和十组／25 条准确案例只维护在[WCS Wiki](../wiki/domains/wcs/specification.md)；本地实时合同优先，知识不得新增能力。

## 发送、回执与异常

发送队列先持久化，独立处理器下发；超时／中断进入待核对，不盲目重发或释放覆盖量。厂商回执须通过认证和任务／设备／位置校验。已发送任务的取消或改派需要厂商协议支持，取消未发送计划不能冒充撤销设备动作。

全部必要程序完成后才按原库存行验证一次。第一步已经发生的物理搬运不能因第二步失败而被“回滚”；unknown 或失败不自动视为完成。

## 设备与未迁移范围

simulation 支持散件和库区模拟；JSON 的散件、库区及真实设备同数据多程序须人工确认能力。HIK／WES 当前仍需载具，WES 仅支持既定库存端点。模拟和 HTTP 桩不等于真实设备联网验收。

统一装箱完成标记、空载具库存池自动搜索、任意新细点回报自动回写、多个物理载具合为一计划，以及旧 ZF 的 MES/E10、CTU、厂商盘点／物料同步等客户动作不属于已迁完的通用能力。

## 升级、版本与证据

模块字段、数据和迁移变化需在备份数据库／filestore 后升级，不能只拉代码并重启。核对库存、人工参数、草稿、版本、发布、计划与任务指纹；不自动转换旧合同或恢复／改写绑定。跨电脑步骤见[Git 协作](../git-sync.md)。

生产接口定义不安装示例正文，历史出厂定义按已知摘要退休；客户修改与版本历史保留。运行正式策略不请求云端。当前 AI 真实生成、批准来源及主库保护见[接入记录](native-wiki-runtime-20.md)；原始迁移来源见[wcs-source-lock.json](wcs-source-lock.json)。
