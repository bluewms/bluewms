## 模块与范围

blue_stock_rules 20.0.1.0.0, AGPL-3, 依赖 blue_stock_base, 已安装到本机 Docker 的 bluewms20 开发库。它不强制安装条码、WCS、AI 或登录界面模块。

| 功能 | 正式行为 |
|---|---|
| 默认负库存保护 | 对库存产品的内部及中转位置, 按 Odoo 单位精度拒绝形成负在手量; 按产品、批次、包裹、货主等 quant 粒度检查 |
| 产品／类别／位置例外 | 仅明确允许的范围可出现负库存; 类别例外不继承到子类别, 位置例外不继承到子位置 |
| 冻结 is_locking | 阻止位置及下级位置的库存进出、新增预留、物理库存属性变更与非空 quant 删除 |
| 禁止入库 block_stock_entrance | 阻止位置及下级位置增加库存, 可以从已有库存位置移出; 可在有库存时启用 |
| 取消与释放预留 | 冻结后仍能释放已有预留、取消未完成作业; 不允许借此增加库存或新增预留 |
| 可用位置及上架准入 | 上级规则传递到子位置, 调整可用空位统计, 被限制位置不通过标准上架准入检查 |
| 同库位拆包／换包 | 在仅禁止入库的位置, 标准库存流程中的同库位内部移动可执行; 完整冻结仍拒绝。服务器核对实际移动行, 客户端不能用 context 伪造许可 |
| 后端保护 | ORM 数量／位置／物理属性变更均检查; 不接受 skip_negative_qty_check 等客户端 context 绕过, 测试环境也实际执行 |

负库存指在手 quantity, 不等于 quantity-reserved_quantity 的可用量。手工超量填报可能先改变预留／可用量, 但完成库存移动时会验证在手量, 失败由事务撤销该次移动。本模块没有额外规定“所有预留永远不超过在手量”。

仅库存管理员可以修改产品／类别负库存例外, 且仍须具备原模型写权限。库位设置沿用 Odoo 的库存管理员和公司访问控制。产品／类别开关是共享记录属性, 不伪装成每个仓库独立设置; 库位例外属于具体位置。
