# 16 版条码终端操作对照

日期: 2026-10-23. 16 版作为前端操作参考,19 版作为扫码处理参考;当前运行框架为 Odoo 20 的 Owl 3. 本轮安装和验收仅在隔离预览,不代表主库交付或全部旧功能迁入.

| 16 版实际交互 | 当前实现 |
|---|---|
| MainScreen 独立应用,大图标入口 | 原生 fullscreen client action;作业、盘库、产品、位置四入口,相机和退出按钮;主题颜色跟随 MuK,图标使用 Odoo 20 的 oi/data-icon |
| WarehouseOperationDisplay 按仓库选择作业类型,显示待作业数 | 读取当前公司和当前用户可见的待作业聚合;按类型进入单据,提供联系人、日期、源单据;批次有独立选择入口 |
| WarehouseOperation 头部显示作业名、位置/包裹和分页 | 固定作业标题,工作区顶部业务分页;按单据+位置组合或源/目的包裹组织,不按固定行数切页;批次保留各所属单据,包裹页的不同位置按行显示 |
| BarcodeLineTransferWarehouse 产品图片、已作业/需求量、选中边框和行按钮 | 点击产品行选择/取消,选中才展开详情、−1、+1、补齐剩余量及铅笔;序列号不提供一次补多件;未盘行显示 —,明确盘零仍是已盘 |
| 扫码后突出对应行并定位滚动,未完成行优先 | 回执使用真实行键高亮和滚动,可选完成置后;位置或包裹唯一匹配时定位对应页;保留用户主动翻页,不被旧回执跳回 |
| EditPopUpComponent 独立数字键盘 | 新 QuantityEditor 组件: 数字、小数、退格、清空、±1、取消/确认,保留图片/位置/追踪信息;输入为明确总数,不把手工总数当作增量;系统软键盘保持收起 |
| 固定底部验证/作业按钮 | 固定本页装箱/WCS/整单验证;验证和装箱有原生确认窗;每枪已保存,原生欠单向导继续处理;盘库只保存实盘,由管理员记账 |
| 从作业进入产品详情再返回 | 保留会话、位置页、数量和行选择;刷新也恢复所在页和选择;搜索/下拉操作结束交回扫码焦点 |

当前工作台使用 Owl 3. 工作台、数字键盘和采集器按功能存放于 `blue_barcode_base/static/src/`.

扫描仍走 Odoo barcode_scanned 总线和串行事件. 单次完整 QR 保留分隔符和空字段,原生 GS1、产品单位、批次/序列号、公司/权限、数量和原生库存流程由固定服务复核. 手工按钮复用已有带版本及幂等编号的数量事件,不另设前端直接写 move line 的通道. 正在补追踪、存在未知结果或未处理队列时禁止手工改数.

16 版的临时加位置/加额外产品、隐式新建调拨、直接改变单据范围没有一并恢复;盘库不提供无盘库单的 quant 写入. 这些行为会改变已确认的单据和 AI 能力边界,应通过正式单据或后续受控扩展处理. RFID/EPC、报废仍属后续范围.

验证: 最终 54 项后端、9 项采集通过;浏览器在桌面及 360 像素 PDA 视口检查选单、连续键盘扫描、翻页和焦点、独立数量键盘、零实盘、批次、详情返回、刷新恢复及取消验证. 浏览器键盘模拟不代替真实扫码枪、PDA 厂商注入方式或相机验收. 具体数值、版本与日志见 [进度记录](barcode-20-progress.md).
