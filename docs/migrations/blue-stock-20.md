## 已完成的调整

- 根据实际容器版本使用 `stock.quant.uom_id` 和库存移动／明细 `uom_id`；迁移单位视图、批次菜单、产品变体动作等实际 XML ID。
- 同一产品多批次的数量汇总，包含负库存调整；零数量记录不冒充有货，混放产品明确显示，不把第一条 quant 当成整个库位。
- 库位层级统计排除锁定、归档及非内部空位，父节点锁定时停止计入其可用数量。
- 容量数量只取单一包裹容量，多类型／无容量时明确置零；按存储类别手动同步，限制整数 0～2000，增补缺失编号并保留已有记录 ID。
- 容量明细添加所属公司与公司访问限制：仓库用户只读，管理员配置；编号同一库位内唯一。已被库存／预留使用的位置不能删除、改号或迁移到另一库位。
- 复用 Odoo 20 原生包裹货主计算，保留包裹使用类型、子位置和消息。清空库存／预留后释放子位置标记，不在计算方法里修改该标记。
- 复制包裹向导保留 1～2000 限制，批量创建新空包裹，不复制库存、嵌套包裹、原位置和子位置，不修改输入复制数量。
- 保留内部移库默认目标包裹和默认装箱类型；不同作业类型的默认包裹配置冲突时要求明确选择，不随机选一种类型。
- 界面模块在首次安装前保存所调整标准菜单／动作的原值；卸载时恢复菜单父级、顺序、名称、启用状态和产品动作视图顺序，防止标准菜单随新顶层菜单一起消失。
- 未加载旧的空模型占位类和未启用的库位 Kanban 动作，未迁移无调用入口的临时字符串修正工具；相关源码来源和 LGPL-3 文本随新模块保留。

## 边界与后续事项

- 本次是源模块功能迁入新 20 工程，不是旧 19 客户数据库升级；没有移动或修改旧 19 目录，也没有迁移旧数据库记录或外部 ID。旧项目升级需要另行设计数据和 XML ID 迁移。
- `is_locking` 本轮控制可用空位统计，不构成完整库存作业锁定；禁止入库／出库的实际约束在后续 `blue_stock_*` 库存约束模块中统一。
- 容量位置目前只检查库存／预留占用。WCS 迁移时必须扩展 `_is_in_use()` 检查在途任务；没有设备任务模块时不能声称已验证设备占用保护。
- `not_all_package`、`is_auto_lot` 保留为后续 ERP/WCS 的配置字段，本轮没有引入这些接口的执行逻辑。
- 调拨验证按钮沿用原界面“仓库管理员可见”规则，不把按钮隐藏当成服务端授权检查；后续角色治理另立合同。
- UI 验证是在独立库、标准 Web 上完成；日常库安装已兼容当前 MuK 模块，但没有完整回归 MuK 的全部桌面／移动端交互，也没有连接真实设备。
- 保存最后成功备份不等于已完成整库恢复演练；配置／代码回退不撤销安装后人员已经完成的库存作业。
