## 模块与资产

- `blue_extension_contract` (LGPL-3)：`putaway_policy/1`，纯 JSON 输入、受限 Python 语法解释器、输出校验。没有 eval、exec、safe_eval、ORM、导入、网络或文件能力。
- `blue_config_asset` (LGPL-3)：场景、标准模板、不可变代码版本、不可变发布快照与审计事件。
- `blue_stock_putaway` (AGPL-3)：候选准入、两个示例、真实明细试算、原生上架接入、散件容量拆分、单据版本固定及分配审计。依赖现有 AGPL `blue_stock_rules`。本轮新实现，没有复制两个旧上架模块的源码或设备逻辑；旧 19 保持原样。
- 用户已确认：腾讯记忆适配并入未来 `blue_ai_client`，不单独安装 `blue_ai_memory`。云端 key 只在服务端配置，不能写入生成代码或暴露在前端。

## 如何使用

库存 > 配置 > 上架策略，新建场景并选择公司、仓库、收货／内部作业类型、上架库区和标准示例。每个公司／仓库／作业类型有一个场景；同批次和同单是可选代码模板，不是两个独立生效开关。组合策略可以在同一份代码内明确优先顺序。

1. 点击“载入标准示例”，查看需求、可编辑代码和三个 JSON 试算样例。
2. 编辑代码和样例预期；保存只影响草稿。
3. 点击“试算与验证”。预期排序全部通过才生成不可变代码版本。
4. 可选择“真实单据试算”，读取已有待上架明细及库存／待入库摘要，不写库存、不改目的地、不固定单据版本。草稿与正式／单据固定版本分别试算。
5. 点击“发布生效”。再次执行样例，核对草稿摘要和基础版本，再更新场景唯一正式发布指针。
6. 新作业在原生分配／明细录入更新／实物完成前调用策略。单据首次分配固定准确发布版本；发布新版本、回滚或归档场景都不会切换已固定作业的代码。
7. 从正式版本新建草稿，修改并发布第二版，再点击“回滚上一版”。恢复上一正式指针，保留两个版本与操作人、输入、输出和原因。

安装只提供两个模板与菜单，不自动建立或启用仓库绑定，避免影响现有作业。库存人员可执行正式策略；库存管理员可编辑、验证、发布、回滚和试算草稿。

## AI 可编辑合同

`blue.config.profile.action_submit_draft(code, tests, requirements, expected_release_id=False, conversation_ref=False)` 是后续专用 AI 工具的草稿入口。以当前用户权限运行，核对基础版本，记录 AI 来源和会话引用；只保存草稿，不自动发布。人工编辑和 AI 草稿经过同一套试算／验证／发布流程。MuK 的工具适配及 Tencent 认证未连接，不能将此接口描述成已完成云端 AI 聊天。

输入为 `request` 和 `candidates`。候选已经限定公司、库区、末级库位、产品、冻结／禁止入库、产品容量、重量及其他待上架占用。候选包含 `same_lot`、`same_picking`、`empty`、`max_quantity`、`fits_all` 等纯数据。

输出 `result` 是候选子集，每项仅有 `location_id`、`score`、`reason`。分数越小越优先，同分按库位 ID 稳定排序。不能返回候选之外的 ID 或重复 ID；空结果在真实分配时停止并提示，不回退到受限位置。

语法支持赋值、一个候选循环、if/elif/else、字典键读取、比较、布尔判断、有限数值运算和 `result.append({...})`。不能定义函数、调用任意方法、导入、while、嵌套循环、访问 Python 对象属性或修改输入。32KB 代码、200 个候选、256KB 输入、2,000 个 AST 节点、30,000 步执行预算。它是受限策略语言，不是通用 Python 沙箱；复杂扩展通过正式模块开发。

云端后续将准确代码、接口版本、校验值、测试和会话引用关联保存；客户对话及专用代码按项目隔离，不自动公开到 GitHub。Odoo 保留准确正式资产，云端检索记忆不替代本地可恢复代码。

## 首期业务边界

- 两个示例都是“优先集中，其次空位，再考虑其他合规位置”，不是禁止混批／禁止混单。无可用位置停止。散件数量超过单库位剩余容量时拆分明细，并保留总数量、单位、批次、货主等维度。
- “同单”指同一 `stock.picking`。待上架明细提供正在占用的位置；已完成明细的历史位置只有在对应产品／批次／货主仍有正库存时提供优先依据。库位排空或作业取消后不继续优先。首期不提供精确库存来源追踪或单据独占库位；混合库存不能凭历史关联证明货物仍属于原单。
- 同批次示例对有追踪的产品要求实物执行前选择已保存的批次；新批次名自动创建流程尚未桥接。在批次尚未填写时不自动固定同批次策略版本。
- 首期仅支持散件。绑定策略场景的包裹明细在实物执行前明确阻止，避免拆散整包；包裹、托盘、设备、WCS 和条码专用交互后续扩展合同。
- 仓库行锁串行化本模块内的分配，目的数量计入其他未完成明细，并在实物完成前重新检查／必要时重新分配。原生手工盘点／不使用此策略的业务不是该锁的参与者；容量不是新增全局 quant 硬约束。
- 库位冻结、禁止入库及负库存的服务器保护继续由 `blue_stock_rules` 执行，生成代码不能绕过。
