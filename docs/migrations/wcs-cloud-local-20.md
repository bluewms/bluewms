## 当前行为

WCS与上架共用PR #4的聊天浮窗，保留业务表单和地址，可放大、恢复、关闭和重开。新WCS会话进入“WCS生成策略”Task，绑定用户、公司、资产、合同、草稿摘要和正式基础版本。仅支持WCS /4的新AI入口，旧合同与正式策略保留，不自动转换、发布或改绑。

生产WCS只安装“WCS增强接口 /4”基础运行定义，不带示例代码、测试或需求。原18个出厂定义归档，仅对摘要与原出厂内容相同的字段清空；管理员修改过的内容保留，客户草稿、版本、发布历史不动。回归示例仅在tests/data中加载，Wiki文档是供用户审阅发布的来源，Odoo不扫描这些本地文件作为知识。

只读工具沿用同项目bluewms-policy-authoring Skill bridge。上架仍读01/03/04，WCS读01/06/07。WCS要求当前合同批准声明、06/07资源的hook/合同批准头标，以及metadata.wiki_source中的真实Wiki ID和正整数版本。读取后固定Skill版本、正文SHA-256和Wiki来源，保存至草稿与版本参考记录；无本地或跨hook回退。旧本地引用会话在读、提交、验证入口都必须重新打开。

未发布WCS知识时，AI工具明确报错且不改草稿。无AI基础生成和既有正式策略继续本地离线执行。AI只有读取、保存和验证草稿工具，没有发布、设备、任意ORM、文件或shell权限。

## 用户最后写入

使用[Wiki离线发布资料包](../wiki-publication/wcs-v4/README-用户最后写入.md)，更新既有项目Wiki与已有Skill，不新建同名孤立库。保留原上架03/04、既有02/05和无关资产。

用户批准Wiki后，将平台实际返回的Wiki ID、版本填入metadata-after-user-approval.json的wiki_source，合并至Skill新批准版本；再填写upload-receipt.json的真实版本和URL。当前这些字段为null，没有伪造云端地址。客户端自动读取批准metadata，不需要把云端ID硬编码到本地。

从WCS /4资产页打开新浮窗，先只读调用blue_read_code_asset，核对hook=wcs_creation、contract=wcs_creation/4、真实Wiki来源和01/06/07正文，再按正常流程生成、验证和人工发布。用户未完成云端写入前，WCS AI知识读取明确拒绝；本地交付不代表云端发布完成。
