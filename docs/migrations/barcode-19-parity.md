# 条码 PDA 操作与 19 版对照

日期: 2026-10-21. 针对用户对 PR #15 首版的操作反馈继续修正,不改变已确认的分组分页、盘库单及 AI 权限边界.

| 19 版工作原理/参考 | 当前处理 |
|---|---|
| `components/main.js` 和 `main_menu/main_menu.js` 订阅 `barcode_scanned` | 作业、查询和首页共用 Odoo 条码事件总线;作业页不显示条码输入框或逐枪确认按钮,相机也进入同一业务入口 |
| 键盘采集、移动端隐藏采集输入 | 采集器只在当前活动工作台挂载;复用原生移动端隐藏输入,不唤起软键盘;编辑数量、搜索输入、相机/原生对话框、页面失焦及离开工作台时暂停或清理不完整输入 |
| 原生采集中的分隔/清洗 | 不按分号或竖线拆一次 QR,不从业务文本删除 Control/Shift 等单词;保留空字段、前导零和 GS1 分隔符,每次完整采集只发一个事件 |
| 扫描队列和反馈 | 串行写入、最近扫描、成功/错误提示及可用时震动. 确定被服务端拒绝的误扫不计数,可直接重扫;网络结果未知仍按原事件 ID 核对,不当成新枪重加 |
| 商品、批次、包装码、位置解析 | 继续使用原生 GS1、包装单位换算与纯数据策略,固定服务校验当前公司/单据和库存维度 |
| 已选行与下一枪产品匹配 | 选中过 A 行不会阻挡下一枪 B 商品;同商品的明确行选择仍有效,跨单或有追踪歧义时不猜测 |
| 批次/序列号的后续扫描 | 产品需补追踪时不先加数量;位置/包裹扫描不能静默清空待补扫产品,必须补齐或明确取消 |
| 来源/目的位置与扫描上下文 | 位置只在实际单据范围内确认;当前页和已确认位置冲突时要求补扫,不能串组计数 |
| 原有预留与已作业量 | 数量事件区分预留和已扫;单移动行重新进入时,应作业量仍取单据需求,不能把已扫 2 显示为应作业 2 |
| 保存、装箱和验证 | 每个有效事件已经持久保存;返回/退出释放写会话而不清零数量. 装箱、验证和欠单使用原生入口,保留固定 WCS 约束 |
| 会话恢复与单据状态 | 已释放且没有待确认事件的旧会话不再恢复成只读工作页;会话关闭不代表库存单已经完成,可以重新选择未完成作业 |
| 16 版产品信息交互 | 专用产品/位置查询页,支持直接扫描和从列表选择;提供基本资料、图片、库存分布、位置层级以及产品/位置相互进入详情;无库存时仍显示资料 |
| 作业类型配置 | 只使用原有同一 notebook,条码为 WCS 后的独立页. 未安装 WCS 桥接时条码位于硬件页之后,基础条码模块不强制依赖 WCS |

## 验证

- 48 项条码后端回归通过,包括页签顺序、普通作业员权限、产品/位置资料、子位置库存、查询类型限制、选中其他产品后继续扫码、待补批次保护及重进作业需求量.
- `node scripts/test_barcode_capture.mjs`: 9 项采集测试通过,涵盖完整 QR、无结束符、双结束符、移动隐藏输入、GS1、真实重复扫码、编辑暂停及卸载清理.
- 8071 实际浏览器: 无条码框直接键盘扫码打开单据、误码后直接重扫恢复、产品/位置相互查看、返回作业保留数量及原单据需求.

## 保持的边界

19 版通过扫描位置隐式新建调拨、无盘库单回退 quant 调整、任意模型/字段写入不恢复. 指令码不能用来调用任意方法. 单次跨多行自动分摊、整包自动实盘、RFID/EPC 和报废仍按原计划处理. 真实 PDA 型号、厂商注入方式、相机权限与现场连续吞吐仍需实机验收;浏览器键盘模拟不替代现场证明.
