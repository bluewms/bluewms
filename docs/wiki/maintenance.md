# Wiki 维护与发布约定

更新：2026-10-17。适用于本目录和对应的 TencentDB-Agent-Memory 项目知识。

## 文件职责

- `basics/`：长期共用的分工、流程和配置方法，不嵌入业务示例正文。
- `domains/<领域>/specification.md`：该类合同、能力边界和生成规范，不能把规划接口写成已开放。
- `domains/<领域>/examples/`：一个案例一个文件，保留准确代码、试算输入、期望和验证证据；`README.md` 作案例目录。
- `history/`：按日期保留配置纠正、联调与历史决策；现行规范不持续累积排错流水。
- `publication-map.json`：人工发布时使用的来源映射，不是已部署发布器或自动同步配置。

## 状态分别记录

| 知识状态 | 含义 | 能否作为已验证可执行示例 |
|---|---|---|
| `planned` | 设计／需求样例，合同或 AI 入口尚未具备 | 不能 |
| `draft` | 文稿或代码候选，验证／审阅未完成 | 不能 |
| `verified` | 指定版本下的准确代码和测试已验证，证据齐全 | 还需按云端批准流程发布 |
| `deprecated` | 已失效或被替代，保留原因及替代链接 | 新生成不再选用 |
| `historical` | 某个日期的证据，不能覆盖当前规范 | 仅作追溯 |

文档状态、业务实现状态、云端批准／发布状态是三件事。`verified` 不是自动给云端写入 `approved=true`，Git 合并也不会自动更新 Wiki／Skill。新目录中的整理文稿尚未重新发布；当前 Odoo 继续读取原已批准资源。

## 新增一个案例

1. 复制 [示例模板](templates/example-template.md)，保存到对应领域的 `examples/<稳定名称>.md`；不要把新案例追加到综合配置说明里。
2. 写明稳定知识 ID、hook、合同／模块版本、需求、适用范围、限制、准确代码、测试和预期。示例 ID 不使用某台数据库的记录 ID。
3. 用同版本受限解释器验证所有声明的用例；涉及业务约束时补真实业务回归。纯代码试算通过不能证明托盘容量、公司权限或设备动作正确。
4. 记录日期、来源提交／交付记录和结果，在该类示例目录添加链接。现有测试 fixtures 是固定回归证据，不能把修改文稿当作已经同步测试。
5. 通过任务分支和 PR 审阅。`main` 受保护，不直接推送或强推覆盖。

规范变化先更新该类规范，并确认本地合同是否也需正式模块变更；只有文档变化不能开放新字段、语法或动作。

## 发布到云端

人工编辑来源在本目录；云端是 AI 使用的批准发布版本。云端新增经验先作候选，审阅后回写来源、验证，再正式发布，避免两套正文长期分叉。

当前按 [发布映射](publication-map.json) 选择来源章节，发布前核对内容、状态、适用版本和大小。映射不是把全部文件全文拼接的指令：面向人工的背景、历史和维护说明可留在 Wiki，当前 Skill 只收录生成所需的精简说明及准确代码／测试。规范与示例在 Git 内独立维护；兼容现有客户端时仍可汇编成固定云端资源，不必把人工目录与云端资源目录强行一一对应。

现有客户端依赖三个固定路径。未同时升级并验证客户端前，不删除或改名这些资源；重组文档不等于修改运行时路径。示例资源仅收录 `verified` 案例，四类 `planned` 页面不得混入批准上架示例。

记录发布清单：来源提交、所含知识 ID／合同版本、正文摘要、云端资源 ID／版本／批准状态、操作者和日期。公共 Git 只放非敏感证据，凭据与原始回执留私有记录。用业务用户验证正文、共享和隔离，新会话确认版本；已有会话继续固定首次版本。

发布前有备份，发布失败不替换批准正文；失效知识保留替代关系，不能追溯修改已经冻结的本地代码版本。当前 32 KiB 上限计算整个 bundle 的 UTF-8 JSON 字节，含 Skill 主文、三个资源正文和包装字段，不能只统计代码。接近限制时先调整检索／资源方案并完成客户端验证，不直接扩充到运行工具无法加载。

## 修改原有说明或配置

通用流程更新 `basics/`；实际服务器变更另记日期、旧值／新值和验收。旧记录加替代链接，不把历史健康检查、测试或版本号改写成今天刚完成。引用其他页面时使用相对路径，不复制第二份同名规范。
