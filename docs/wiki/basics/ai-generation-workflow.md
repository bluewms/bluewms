# AI 生成工作流与工具边界

状态：上架已实现；其他四类按各自合同规划。更新：2026-10-17。实现依据：开发提交 `ad35793`。

## 当前上架流程

需求 → 从场景页面打开会话 → 绑定本地资产与身份 → MuK 主持工具循环 → 云端模型／身份初始化 → 读取真实资产与批准知识 → 提交草稿 → 本地验证 → 用户审阅发布 → 本地业务执行。

在“库存 → 配置 → 上架策略”点击“AI 生成 / 修改”。新会话固定资产、公司、合同、草稿摘要和正式基础版本，云端选择当前用户的 Agent 和“上架策略”Task。页面上下文可以变化，固定资产绑定仍由服务端维护；不会因为打开另一张表单就允许模型改任意记录。

## 当前三个工具

| 工具 | 实际返回／执行内容 | 不包含的能力 |
|---|---|---|
| `blue_read_code_asset({})` | 当前草稿全文、需求、测试、`contract_schema`、草稿摘要、正式版本 ID，以及批准的云端知识正文 | 不遍历全部 Odoo 源码，不自动读取全部正式版本全文，不返回本地模板示例 |
| `blue_submit_code_draft` | 核对已绑定资产、并发摘要、正式基础版本及成功知识读取；保存 AI 草稿和知识来源 | 不发布，不修改其他资产 |
| `blue_validate_code_draft` | 用本地受限解释器执行本次测试，创建不可变验证版本并返回结果 | 不执行任意 Python、ORM、网络、文件或发布操作 |

读取时本地同时给出接口版本和机器可读合同。合同来自当前已安装的解释器及上架输入定义，不是自动扫描 Odoo 的全部 API。

正式代码／发布快照保存在本地数据库；当前读取工具只给出当前正式版本 ID。若以后需要给模型读取正式代码差异，必须增加明确且受权限约束的返回，不把“本地保存”写成“当前工具已经返回”。

## 云端正文如何进入请求

`blue_ai_client` 通过当前代理会话读取固定 Skill `bluewms-policy-authoring`：先搜索可见资产，再核验名称、active 状态、`approved=true`、用途和资源目录。当前仅读取项目治理、合同参考、上架示例三个固定资源；真实路径见 [发布映射](../publication-map.json)。

会话固定首次知识版本及正文／资源 SHA-256，后续读取要求一致。单次响应上限 128 KiB，整体知识上限 32 KiB，读取有 30 秒预算及逐请求超时，拒绝重定向。模型不能指定 URL、路径、身份、Skill ID 或命令。读取失败不回退到本地通用示例，也不能用 `ask_user` 假装读取上下文。

模型实际收到：系统指令、用户需求、已允许工具的参数结构、历史对话／工具结果、必要运行上下文，以及读取工具返回的资产和知识。认证 Key 通过 HTTP 头使用，不作为提示词正文。Wiki、Code Graph 和其他 Skill 不会仅因已关联就自动变成可调用工具。

## 本地保存、验证与发布

`blue_config_asset` 保存当前草稿、本次测试、验证版本、发布快照及审计。知识来源记录其 ID、版本和摘要；这些引用随代码版本保留。运行使用准确的本地代码，不从云端摘要或聊天重新生成。

用户查看代码和试算结果，必要时做真实单据预览，再发布。正式版本改变或草稿被他人修改后，旧会话拒绝覆盖；身份、公司、合同变化时重新从场景页面打开会话。已发布策略仍可在云端不可用时执行，已分配作业保留固定版本。

## 扩展其他四类之前

每类独立定义输入、输出、允许语法、权限、副作用、验证格式及业务执行点。上架的 `location_id / score / reason` 和 `expected_order` 不能直接套用于 WCS；现有 WCS v2 采用任务输出和 `expected_tasks`，其 AI 工具仍未开放。

增加字段、模型、前端组件、第三方库或网络协议由正式模块交付；知识或生成代码不能自行新增系统能力。后续云端后台任务若接管编排，须先定义协议与幂等，不能与 MuK 重复执行同一工具循环。
