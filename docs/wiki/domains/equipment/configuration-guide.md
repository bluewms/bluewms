# 设备类别接口配置与 AI 使用

适用合同：device_protocol/1。知识状态：verified。更新：2026-10-18。是否可生成仍以实例安装及平台批准为准。

1. 在设备类别中人工新增记录，选择“可编辑 HTTP 接口”。保留公司、负责人、IP 地址、任务路径、App Key／Token、App Secret、回调凭据的人工配置；不让 AI 改写。
2. 填完整 HTTP(S) 地址和相对任务路径。TUSK 使用 `/rpc/createTask`。人工选择下发认证；旧 TUSK 可不附加认证。所属设备统一使用类别参数，不读取设备历史地址或密钥兜底。
3. TUSK 启用旧 TUSK 回调地址，任务号字段为 taskId，保留旧版无附加 Token 方式。其他单条 JSON 接口使用 `/blue_wcs/v1/categories/<类别编号>/callback`，人工选择兼容方式或 Bearer。当前不支持任意动态注册路由或一条报文处理多个任务。
4. 人工选择是否允许包裹子位置回写；允许实际库存库位回写时，必须设置同公司的允许目的库区。仓库等固定业务编码放非秘密参数，身份认证只使用专用密钥字段。
5. 保存类别后建立空接口资产，不载入本地标准示例。设备从设备页面新增并选择类别；有明确设备编号时填写厂商设备编码，回调 deviceId 必须匹配该值。
6. 在类别页点击 AI 生成／修改。助手通过原生 Wiki 搜索、完整读页及读取准确绑定资产，生成代码和三个阶段的试算，再保存、验证草稿。使用团队既有“设备连接接口”Task，不新建 Task。
7. 审阅报文、接受条件、完成及位置更新结果，再人工发布。报文试算不发设备请求。真实任务仍走现有 WCS 持久发送队列，接口代码不能直接发请求或验证库存。
8. 在 WCS 作业的“设备协议与实际位置”页查看固定版本、计划位置、实际完成库位、回报点、子位置及原文。未知／多个匹配、冻结、超容量或其他不一致进入待核对。
9. 修改先新建草稿、验证和发布。已有任务继续用原版本，回滚只改变后续代码。有未结束任务时不能更换连接、类别或允许范围；已完成库存不能通过改回调撤销。

首期是 HTTP／JSON POST、响应解释和单条最终完成回调。TUSK 见 [准确案例](examples/README.md)，其他厂家见 [协议参考](reference/legacy-interfaces.md)，后者不代表完整迁移及真实设备验收。
