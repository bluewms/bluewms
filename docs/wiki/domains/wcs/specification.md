# WCS /4 AI 生成规范

hook：`wcs_creation`。适用合同：`wcs_creation/4`。更新：2026-10-18。本地实现与声明用例已验证；新草稿仍需本次试算及人工发布。实际能力以当前本地工具返回的 `contract_schema` 为准。

按[配置语义](configuration-guide.md)、[合同核对附件](wcs-creation-v4-contract.json)和[十个独立案例](examples/README.md)阅读。附件用于核对该版字段，不替代本实例实时合同；旧 /1–/3 的输出与历史综合文稿不能直接用于 /4 新生成。

## 两个阶段

全部有效基础行先进入 `lines` 阶段，每行必须明确 `create`、`wait` 或 `exclude`，不得通过遗漏行过滤；同时声明数量依据、组合及物理位置来源。固定服务复核后，对每个就绪组运行 `tasks` 阶段，返回 0–4 个任务。

同货连续程序用 `repeat`；改变物理路线的接力用 `relay`。后续 goods 必须依赖上一 goods 的 `end`，不能无依赖并行。同组多个 goods 任务共用一份物料计划，库存仅按原业务行最终记账一次。空载具步骤不增加货物数量，也不代表已经具备空载具库存池自动分配能力。

## 系统约束

人工 WCS 类型、设备类别、设备、任务类型及自动开关不能被生成代码改写。入库实际确认、合法库存／预留、公司／冻结、整载具实际货物完整、数量覆盖和幂等均由固定模块强制复核。

单行 `picked`、同载具全部确认、整单全部确认、达到显式重量阈值是不同条件。`package_max_weight` 是最大运输重量，不能当成最小满载阈值。人工启用适配能力仍需设备现场确认，模拟与 HTTP 桩测试不代表真实设备验收。

## 知识与草稿

先读取绑定资产、完整合同，再通过实际可用的只读知识工具取得本领域规范与相关完整案例。不能读取上架案例替代，也不能在云端缺失时回退到本地示例。

/4 测试使用 `expected_result`，覆盖 `lines` 与 `tasks`；旧合同的 `expected_tasks` 不适用。提交并验证草稿后，由用户审阅发布。不得自动转换旧资产、重绑作业类型、改写已发布 /1–/3 或执行设备任务。
