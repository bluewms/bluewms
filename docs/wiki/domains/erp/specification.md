# ERP 接口 AI 生成规范草案

hook：`erp_mapping`。知识状态：`planned`。更新：2026-10-17。AI 运行合同：尚未定义；当前未开放生成、提交或执行工具。

## 计划生成什么

在正式 ERP 适配器提供的纯数据输入上，生成产品、主数据或单据字段映射及有限业务判断。网络连接、认证、分页、幂等、重试和数据库写入由固定模块负责；AI 不生成整个 ERP 客户端或任意 ORM 代码。

## 合同落地前必须确认

| 项目 | 需要明确的内容 |
|---|---|
| 输入 | 外部数据版本、单据／行标识、字段类型、单位和时区、当前公司及允许的业务映射 |
| 输出 | 允许设置的字段、类型、忽略／拒绝的原因；未声明字段必须拒绝 |
| 幂等 | 外部单据／行的稳定键，重复接收、更新和取消由固定业务流程处理 |
| 权限 | 公司、产品、单位、库位和单据范围由本地授权校验，不由生成代码扩大 |
| 执行 | 先试算差异，再按批准版本提交；写入事务及错误恢复由模块负责 |
| 测试 | 正常映射、缺必填、未知枚举、单位不匹配、重复数据及跨公司拒绝 |

以上为待设计要求，不是当前可用字段或输出 schema。待确定本地合同和验证格式后才增加可执行代码页；不套用上架的候选／评分输出。

## 生成和维护约定

只能引用已注册映射与本地已允许数据；不从缺失字段猜测公司、客户、产品或数量。无法映射时返回明确诊断，不能直接使用管理员权限兜底。接口文档、映射字典、客户脱敏需求与批准代码分开标记版本。

需求案例见 [ERP 示例目录](examples/README.md)。新增能力先完成适配器、合同、试算与业务回归，再更新本文的实现状态和云端批准案例。
