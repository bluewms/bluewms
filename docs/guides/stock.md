# 库存基础与硬约束

适用模块: `blue_stock_base`、`blue_stock_rules`、可选 `blue_web_theme`。更新: 2026-10-26。

## 设置与日常使用

库存基础扩展库位、容量位置、包裹、批次和数量汇总。品牌界面独立提供产品、包裹、位置菜单。只安装库存基础即可工作，不要求 AI、WCS 或条码。

- 位置表单可维护原生条码，显示所属仓库、空位/有货状态和只读下级库位；位置列表显示条码并支持按条码搜索，上级位置和移除策略为可选列。安装条码基础模块后显示 Code128 预览，无法编码的值不阻止编辑。
- 库位汇总保留产品、批次、包裹和货主维度；多产品不显示成单一产品，零数量不算有货。
- 容量位置按存储类别配置同步，编号范围 0–2000；已有记录保留身份。被库存、预留或相关在途业务占用的位置不能随意删除或改号。
- 空包裹复制仅批量建立空记录，不复制库存、嵌套关系、位置或子位置。内部调拨和装箱按作业类型的默认配置处理，配置冲突时须明确选择。
- 产品、批次、库位和包裹使用原生库存单位、货主及公司权限。界面隐藏按钮不代替服务端权限。

## 库存规则

| 设置 | 行为 |
|---|---|
| 负库存保护 | 对库存产品的内部/中转位置，按产品、批次、包裹、货主和单位精度拒绝负在手量 |
| 允许负库存例外 | 只有明确批准的产品、类别或位置生效；类别和位置例外不自动继承到子级 |
| 完整冻结 `is_locking` | 阻止本位置及下级的库存进出、新增预留及物理库存属性变更 |
| 禁止入库 `block_stock_entrance` | 阻止继续增加库存，允许移出已有库存；有货时也可启用 |
| 取消/释放预留 | 冻结后仍可释放已有预留、取消未完成作业，不允许借此增加库存 |

负库存检查针对在手量，不把“在手减预留”当作在手量。标准库存完成时执行检查；不能通过客户端 context 跳过。仅禁止入库的位置允许标准同库位拆换包，完整冻结仍拒绝。

管理员设置例外时仍需原模型写权限。产品/类别属性是共享配置，不能冒充每个仓库独立设置。上级冻结及禁止入库限制向下生效，也参与上架准入。

## 部署与扩展

库存基础、硬约束、上架、盘库、ERP、条码各自独立；按业务安装对应模块。旧客户数据和 XML ID 的迁移需单独演练，替换代码目录不会迁移业务数据。

使用 [上架策略](putaway.md)、[盘库](inventory.md)、[条码](barcode.md) 处理对应流程。安装、备份和升级见 [运维步骤](../operations/upgrades.md)，第三方归属见模块原有许可与 [依赖说明](../third-party/README.md)。
