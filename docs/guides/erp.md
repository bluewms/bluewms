# ERP 接口

适用模块: `blue_erp_interface`，盘库关联可选 `blue_erp_inventory`。合同: `erp_mapping/1`。更新: 2026-10-26。

## 接口设置

从设置页的 ERP 接口管理进入，按入库、出库、内部调拨或盘点新建接口。人工维护公司、连接、允许操作/相对路径、作业类型、位置范围、顶层明细数组字段和凭据。每条接口维护独立代码资产及正式版本。

| 方向 | 固定服务职责 |
|---|---|
| ERP → WMS 入库/出库/调拨 | 校验事件及单据/行 ID、主数据和位置范围，通过原生流程建单 |
| WMS → ERP 完成反馈 | 验证库存后保存本次完成及累计量快照，部分完成使用新事件键 |
| WMS → ERP 盘点差异 | 保存调整前账存、实盘和差异；零差异不发送 |
| ERP 响应 | 仅明确成功/拒绝可确认，超时、异常及不明响应进入待核对 |

盘点接口选择准确内部库位，不自动包含子库位，同库位仅启用一个接口。

## AI 代码与主数据

从接口的资产页编辑或打开 AI 浮窗，生成完整代码与本次测试，验证后人工发布。代码只转换 JSON，不获取密钥、不联网、不调用 ORM、不直接建库存单。模型、连接、发送、幂等及业务约束由固定模块处理。

商品按唯一 `default_code`，往来单位按唯一 `ref`，显式批次须存在；未知/重复编码应修正主数据。单位使用商品库存单位的原始名称 `lang=None`。位置条码须在人工允许范围内，空值才使用配置默认位置。

## 发送、核对与版本

多个有序 actions 按顺序持久发送；成功操作不重复发送。固定服务维护 Idempotency-Key，代码不能覆盖。未知结果先核对，不盲目重发。库存完成与 ERP 同步状态分别管理。

仅支持单次 JSON POST 及本地凭据占位符；动态 Token、多步响应传参或新增签名算法需正式扩展执行服务。凭据不得写入代码、Wiki 或试算。

新发布影响新单据，原单与欠单保持固定版本。真实客户 ERP 协议须取得文档、脱敏报文并现场联调；准确试算不等于外部 ERP 已连接。

接口四阶段、完整合同和准确案例只维护在 [ERP 知识](../wiki/domains/erp/specification.md)。生成链路与云端发布状态见 [AI 使用](ai.md)，安装见 [升级说明](../operations/upgrades.md)。
