# 上架增强策略

适用模块: `blue_stock_putaway`；合同: `putaway_policy/1`、`putaway_policy/2`。更新: 2026-10-26。

## 操作步骤

1. 库存 → 配置 → 上架策略，新建场景并选用当前上架增强接口。
2. 填写需求、代码和本次试算，或从资产页打开 AI 生成/修改浮窗。
3. 验证并做真实单据预览，审核后人工发布。
4. 在原生上架规则的“增强策略”字段选择已发布场景。仓库、产品/类别、包装类型、目标库区及优先级继续由原生规则决定。

浮窗保留当前业务页面，可放大/恢复。独立知识讨论位于 MuK AI → 宝蓝业务知识 → 上架策略，讨论入口没有资产写入工具。

## 系统条件优先

固定服务先核对原生范围与优先级、容量、重量、混放、冻结、禁止入库和公司权限；代码只在合规候选中进一步过滤/排序。实际分配先按原生优先级，再按策略分数和位置 ID，不能用低分越过系统优先级。

- 按最外层物理包裹/托盘计数，内箱去重；已上架和待上架占用都计入容量。
- 整托不拆分；散件仅在系统允许时按容量拆分。多产品托盘须满足各自原生规则路径及相关增强条件。
- 同单集中是合规位置中的偏好，不承诺全局最优或库位独占。
- 跨产品同批次按批次号文本比较，不比较产品专属 lot ID。
- 空结果表示本规则未批准候选；原生流程可能尝试其他规则。要实现全流程硬限制，应检查所有相关规则及回退路径。

## 代码与版本

合同只接受纯 JSON 和受限语法；不能调用 ORM、网络、文件或任意 Python。试算预期为 `expected_order`。首次参与业务时固定“作业单＋原生规则”选择的正式版本或无增强选择；新发布/改绑不追溯改变已固定业务。

规范、完整合同和准确案例只维护在 [上架知识](../wiki/domains/putaway/specification.md)，不在工程文档复制代码。通用生成流程见 [AI 使用](ai.md)，升级见 [运维步骤](../operations/upgrades.md)。
