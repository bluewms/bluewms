# 条码与 PDA 作业

模块: `blue_barcode_base`；盘库、AI 和 WCS 分别由 `blue_barcode_inventory`、`blue_barcode_extension`、`blue_barcode_wcs` 接入。更新: 2026-10-26。

## 日常操作

独立全屏首页提供作业、盘库、产品、位置。以 PDA/扫码枪事件驱动，不显示逐枪输入框；相机结果进入同一处理流程。产品/位置查询只读，可查看详情、库存分布及位置层级后返回。

作业先选仓库/作业类型和单据，或直接扫描单号；批次有独立入口。按单据和位置组合、源包裹或目的包裹分组分页，保留真实行归属。点击产品行展开详情、±1、补齐剩余和数量键盘；序列号不提供一次补多件。扫描后定位高亮，可将完成行置后；刷新恢复页码与选择。

盘库必须先开始一张盘库单。未盘显示“—”，首次从零累计，支持明确实盘总数和零实盘；只保存实盘，由管理员在盘库单记账。

## 验证、装箱和 WCS

- 未录入有效数量不能把预留量当作已扫验证；需补批次/序列号时先完成或明确取消。
- 部分/整单验证先核对各产品的需求、已扫和剩余，再进入原生欠单等向导。完成页可继续欠单；批次未扫成员按原生流程保留，可能进入新的自动批次。
- 本页已扫且未装箱的货物才可装箱，装完禁用重复操作。WCS 只通过正式入口，必需 WCS 未完成不能直接验证库存。
- 右上角操作与打印提供原生单据、报表、标签及人工取消。取消批次只解除关系，原作业单保留；退货从已完成单据的原生退回入口处理。

## 计数和恢复

真实重复扫描逐次累计，同次事件重试不重加；完整 QR 保留空字段、前导零及 GS1 分隔符。缺追踪先补扫，歧义须选择；不能从未确认预留量直接累计。

扫描串行保存。明确业务拒绝可核对后重扫；网络结果未知须按原事件重试/核对，不能当作新枪。队列暂停后保留后续输入，不承诺完整离线作业。操作页不计商品，请求/向导期间新扫描不混入操作中的数量。结束后不再计商品，完成页可刷新保留。

| 操作码 | 行为 |
|---|---|
| `OBTVALI` / `OBTPACK` | 当前验证或 WCS 主按钮 / 本页装箱，保留确认 |
| `OBTPROP` / `OBTPRSL` | 作业单 / 送货单打印 |
| `OCDCANC` / `OCDMENU` | 人工确认取消 / 返回首页 |
| `OBTRETU` | 当前允许的原生退货入口 |

## AI 配置及范围

作业类型的条码页位于 WCS 后；公司可设通用解析，作业类型可覆盖。二维码分隔取值、扫描选择和已授权后续动作通过 `barcode_policy/1`，会话固定正式版本，实际扫码不逐次调用云端模型。完整规范见 [条码知识](../wiki/domains/barcode/specification.md)。

不开放任意模型/前端命令或跨多行自动分摊；额外产品/库存维度更改走正式业务流程。RFID/EPC、报废等附加页面按后续计划处理。现场编码、PDA 注入方式、相机和吞吐须实机验收，详细用例见 [条码验收场景](../testing/barcode-scenarios.md)。
