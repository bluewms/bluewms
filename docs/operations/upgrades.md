# 安装、升级和恢复

更新: 2026-10-26。运行命令及私有配置格式以 [Docker 指南](../../docker/README.md) 为准。

## 每次升级

1. 核对分支、提交、实际镜像、数据库和本机安装模块；不把相邻参考源码当作容器运行版本。
2. 停止业务写入，保存客户草稿/版本/发布、人工参数、库存、在途任务及待核对发送的基线。
3. 备份同一时点的数据库和 filestore，检查归档可读与内容；重要升级在独立库恢复演练。
4. 仅升级实际已装且本轮涉及的模块；首次新增模块显式安装。不安装测试夹具，不自动发布示例、改绑旧单或重发 unknown 任务。
5. 核对字段/视图、服务健康及业务基线，再恢复写入；新 AI 会话重新固定已批准知识版本。

Python 改动需重新加载；字段、XML 数据或迁移变化需模块升级。拉 Git 与重启不等于数据库已升级。代码/配置回滚也不撤销已完成的库存或物理动作。

## 常见模块组合

| 功能 | 主要模块 |
|---|---|
| 库存基础/保护/品牌界面 | `blue_stock_base`、`blue_stock_rules`、可选 `blue_web_theme` |
| 盘库 | `blue_stock_inventory`；ERP 同装时使用 `blue_erp_inventory` |
| 上架 | `blue_stock_putaway` |
| ERP | `blue_erp_interface` |
| WCS 与设备 | `blue_wcs_base`、`blue_wcs_extension`、`blue_wcs_protocol` |
| 条码 | `blue_barcode_base`，按需加 inventory/extension/wcs 桥接 |
| AI | 合同、资产、`blue_ai_client` 及对应 MuK 依赖 |

精确依赖与版本以模块清单及 [模块架构](../module-architecture.md) 为准，不按本表无差别安装。

## 旧 WES 专用模块

`blue_wcs_wes` 已退役。旧实例先保留含该模块的源码，核对依赖、原有设备/连接、代码资产、库存及在途任务；存在在途任务时先制定收尾和核对方案。

在隔离副本演练后，通过原生 Odoo 卸载流程移除旧模块，再切换新版代码并升级实际保留的 WCS/设备模块。不能先删除源码再尝试卸载。旧源码可从 Git `f6c6d462e606e683e38f72cd8d003913891b4495` 找回；厂商资料留在设备 Wiki 参考区，不是已实现能力。

## 跨机器与旧客户库

每台机器使用自己的配置目录、Key、Agent、数据库和附件。Git 不同步业务数据与云端批准状态。旧客户库的模型/XML ID/历史业务映射单独设计，先演练再迁移。
