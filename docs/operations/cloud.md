# 云端服务与用户接入

更新: 2026-10-26。本文面向管理员，不上传到 AI 生成 Wiki。

## 服务职责

| 服务 | 职责 | 内部基线 |
|---|---|---|
| Hub/Knowledge | 页面、索引、原生 Wiki 工具 | 面板 8125、知识服务 8424 |
| Core | 用户、团队、Agent、Task、ACL 和资产元数据 | 8420 |
| Proxy | 模型代理与会话身份、上下文 | 8096 |
| BlueWMS 只读网关 | Odoo 身份、知识范围、批准与摘要核对 | 回环 8430，HTTPS `/odoo-wiki/v1/` |

实际地址、实例 ID 和凭据只存私有部署配置。网关使用固定回环 Core/Knowledge 服务，不接受模型自选地址、Wiki ID 或身份。源码及部署模板在 [docs/cloud](../cloud/README.md)，正式 Odoo 发行包排除整个 docs。

## 一个项目、六个 Task 和六个 Wiki

团队共用上架、WCS、ERP、设备、条码五个业务 Task 和日常 Task。用户保留自己的 Key/Agent，会话选择既有 Task，无需预先声明 Task-Agent 关联；不要为新用户复制一套 Task，也不把创建者等同于使用者。跨客户数据隔离使用团队和 ACL。

知识按通用库＋五类业务库维护。Odoo 会话固定当前合同、真实身份、批准版本和正文摘要；原生搜索为 BM25，目录不等于正文。未批准或合同不匹配时拒绝生成；只读网关没有业务发布能力。

本地能力与云端状态分别记录，当前六库清单见 [逻辑注册表](../architecture/native-wiki-knowledge-registry.json)，准确发布状态见 [发布记录](../wiki-publication/README.md)。旧 Skill 可供历史客户端使用，当前生成链路不以其兜底。

## 新用户接入

1. 建立用户和项目成员关系、准确 Agent，使用该用户自己的业务 Key。
2. 绑定现有通用＋五类 Wiki，核对团队可读性和 Core ACL。
3. 核对团队既有六个运行中 Task；缺失或重复由管理员处理，不由运行时自动建任务，也无需逐用户调用 `task-agent/link`。
4. 在 Odoo 填写业务连接和 Agent 名称，不填写云端服务管理凭据。
5. 新开业务会话，实际检查身份、搜索、全文读页及合同。仅 HTTP 200、资源可发现或只有一个候选 Task 都不代表路由正确。

## 会话选择与正式关联

Odoo 已统一处理代理的团队、Agent、Task 初始化问答；五个业务入口也会先取得经校验的准确 ID，通过 `x-team-id`、`x-agent-id`、`x-task-id` 交给代理。初始化完成写入的 participation log 只用于展示实际参与者，不等于 `task-agent/link` 声明关系，两者均不替代团队成员和知识 ACL 校验。

已有声明关系可以保留，但不再作为业务身份准入条件。退出团队、Agent 归属不符、业务 Task 缺失/重复/停用及知识未授权时仍拒绝。普通用户 Key 不需要增加管理任务的权限，Odoo 不保存云端管理凭据。

## 备份与排错

改知识/批准元数据前按 [发布流程](knowledge-publication.md) 备份数据库、准确目录及服务配置；SQLite 备份须包含已提交 WAL。修改网关代码后跑本地测试、核对配置再重启专用服务，保留可恢复版本。

依次检查服务健康、有效团队成员、本人 Agent、唯一运行中 Task、知识固定绑定、ACL、ready、批准合同、版本与摘要。版本漂移要求重开会话，不改用历史副本。失败日志不回显 Key、客户数据或整页正文。

个人聊天默认私有；测试问句不作为长期用户画像。公共经验先脱敏审阅再入库。知识发布不修改客户本地正式策略，不创建新的团队/Agent/Task。

## 生成前的需求澄清与必读页

每个代码会话先读绑定资产, 再搜索并完整读取通用生成步骤、五类入口需求澄清规则、本领域规范和匹配案例. 本地与云端提交复核都要求 `basics/ai-generation-workflow.md` 和 `basics/requirements-clarification.md` 的当前批准引用; 只有目录、摘要或任意其他通用页均不能代替.

模型依据 Wiki 的五领域清单识别未决业务选择, 单独调用 `ask_user` 后进入等待; MuK 运行器跳过同一模型响应中的其他工具调用, 防止边问边写. 这不能机械证明所有业务歧义都已识别, 因此必须用真实模型的含糊需求回归检查提问及 Wiki 调用记录. 信息完整时不强制额外确认. 本机能力缺口只报告, 不通过用户同意虚构执行能力.

规范发布后旧知识版本会话需重开. 新规则不安装 Skill, 不发布或改写既有客户策略.
