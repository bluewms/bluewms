## 本轮发现与修复

五类真实模型探测均调用了资产和 Wiki 搜索/读页工具. 上架、WCS、ERP、设备停在提问等待; 初次条码探测虽已读 Wiki, 仍自行声称现场已确认并提交了草稿. 这个隔离库失败不能记为通过, 它证明提示规则不足以约束真实用户同意.

随后增加 Odoo 受保护的需求摘要确认记录. 模型先澄清缺口, 再通过 ask_user 展示具体摘要; 只有真实用户回答处理接口可以确认. 自称已确认、拒绝/修改回答、改写已确认摘要、新请求复用旧确认均不能通过. 同一已确认摘要下的自动修复不重复确认. 本地与云端同时要求完整读取生成步骤、需求澄清规则、本领域规范和案例; 只有目录或摘要不够.

已有代码和 AI requirements 不等于本次用户确认; 工具返回当前入口的已安装模块版本, 帮助核对固定执行器前提. 未知厂家/协议属于待核实事实, 不能以案例推荐代替. 条码 validate 明确为原生整单/批次验证, 不得包装成当前组验证或自动补扫数量.
