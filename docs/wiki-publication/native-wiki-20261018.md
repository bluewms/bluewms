## 合理性复核与准确内容

- 通用资料仍只服务 Odoo 内增强代码生成，不包含 Git／Docker／云服务器运维教材。
- 移除 Wiki 对旧工程综合文稿的依赖；WCS /4 只链接当前分篇规范、合同附件与完整案例。
- 工具步骤以本会话实际提供的能力为准，不让 Wiki 声称不存在的工具已部署。必须取得完整正文，不能只凭目录或摘要生成。
- 保留上架系统优先、托盘容量、跨产品按批次号文本比较及未绑定回退规则的限制；“同单集中”不承诺全局最优或位置独占。
- WCS 保留逐行 create/wait/exclude、repeat/relay、数量覆盖、设备人工授权和库存一次记账；旧合同与正式资产不转换。
- ERP／设备／条码保持 planned，无伪造的可执行代码或 schema。案例格式页明确是模板。

隔离测试库中，13 个示例的代码与完整测试逐字匹配源 fixtures，34 条声明试算全部通过；WCS /4 合同附件与实际解释器 `_describe` 完全一致。Wiki 相对链接全部在目录内有效。可复核脚本为 `scripts/validate_ai_wiki.py`，仅允许 `*_test` 数据库。

## 上传与索引方式

写前备份云端 Knowledge／Metadata 数据库及六库目录。通过标准 `wiki/page/write` 写入准确正文，带来源提交、路径、合同、状态、摘要和 `locked: true`。同库保存 `source-snapshot.json`，用于逐页追溯与复核。

使用标准 `wiki/ingest` 建索引。该版必须存在 raw 来源才允许 ingest，且 LLM 抽取只扫描 Markdown；因此保存 JSON 来源快照并索引已经审阅的精确页面，不让模型重写代码与测试。全过程未直接改 Knowledge 数据库或补造 ready／版本状态。

索引 ready 后通过标准 `tools/list`／`tools/call` 逐页读回，29 份正文及摘要全部一致，再登记平台资产状态和批准页白名单。后三类候选库即使 ready 也保持 `approved=false`、`generation_ready=false`。旧 Skill v4 与旧离线候选包保留原样。

## 模型问答的验证范围

从本机 Docker 的隔离 Odoo 库调用现有 `BlueCloudProvider`，使用本地已配置用户的业务 Key／Agent／Task，通过现有 HTTPS 模型 API 请求真实模型 `glm-5.3-Flash`。验收工具循环提供两个临时只读工具，内部调用腾讯标准 search／read_page；标准工具发现先通过 tools/list 完成。初始提示只有问题、资源目录和工具说明，没有预先填入答案或知识全文。

知识 API 的验收传输使用临时 SSH 只读转发。服务端核对当前业务 Key、所属 Agent、团队、资源绑定及 Core ACL；按 common＋当前领域限制范围，只读发布白名单，检查 ready、版本与完整正文摘要。模型必须先搜索，再读取本轮搜索返回的页面。planned 资料只可用于需求问答。

这验证模型能通过实际检索取得知识并据此回答，**不等于 Odoo 页面中的正式工具已切换**。正式 `blue_read_code_asset` 仍调用固定 Skill bridge；新的常驻 HTTPS 转接、会话引用保存、提交前引用复核与前端真实生成闭环仍需接入。此处临时工具只用于验收，不对外开放 shell、管理 API 或任意地址。

8 组真实问答均完成搜索和全文读取，经逐项对照实际正文核对通过。共 16 次标准搜索、21 次完整读页；问题、真实回答、引用和摘要保存在[脱敏验收结果](native-wiki-20261018.qa.json)。这是本次八组问题的结果，不是穷尽性准确率保证。

| 问题组 | 核对结论 |
|---|---|
| 通用信息来源与发布权限 | 准确代码只指绑定资产；AI 不能直接发布 |
| 上架容量与跨产品批次号 | 10 托盘系统容量／优先级保留，按批次号文本比较 |
| 上架回退与同单集中 | 不把当前规则的空结果误说成全局禁放，也不承诺独占或最优 |
| WCS 同数据双程序 | repeat、上一 goods end、数量只记一次、expected_result 均正确 |
| WCS 重量阈值与确认范围 | 最大运输重量不当最小阈值，缺数据／不足等待，载具与整单分开 |
| ERP 需求 | 幂等与未知商品的责任明确，正确说明 planned |
| 设备需求 | 断线／未知回报不算完成，不由 AI 建连接发指令，保持 planned |
| 条码需求 | 不开放任意 JS、正确说明扫描顺序及重复数量，保持 planned |

测试只读，未保存 Odoo 聊天、策略草稿或正式版本，没有执行发布、设备任务或库存变更。隔离数据库和附件在证据保存后删除；云端模型调用日志由平台按既有设置保留，不能把这些测试问句当成新的已审核业务经验或用户人格。

## 后续维护

维护流程为：改来源 → 核对同版本合同 → 在隔离库验证准确代码／测试 → PR 审阅 → 授权后逐页发布 → 建索引 → 读回核对 → 更新批准清单 → 用业务用户测试搜索、读页与回答。Git 提交和合并均不会自动覆盖云端正文。

发生正文或版本漂移时拒绝继续混用；平台没有已验证的历史版本读页参数。恢复依靠准确来源提交和私有发布包，不能声称仅凭旧 Wiki 版本号即可恢复全部正文。
