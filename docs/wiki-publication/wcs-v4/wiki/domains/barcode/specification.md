# 条码扫描策略 AI 规范草案

hook：`barcode_policy`。知识状态：`planned`。更新：2026-10-17。AI 合同、工具和允许前端动作清单尚未定义／开放。

## 计划生成什么

在已支持的条码页面与正式模块能力内，生成条码解释、校验、扫描顺序或已注册动作选择规则。扫描采集、页面组件、网络请求、库存操作及界面反馈由正式模块处理，不向客户开放任意 JavaScript 执行。

## 合同落地前必须确认

| 项目 | 需要明确的内容 |
|---|---|
| 输入 | 原始条码、编码规则版本、当前作业／行／界面步骤和已确认状态 |
| 输出 | 已解析字段、校验结果或允许动作及明确原因；不能虚构前端 API |
| 顺序 | 货位、商品、批次、托盘、数量等扫描阶段与纠错路径 |
| 权限 | 公司、单据、行和已允许业务操作由本地复核 |
| 重复 | 连续重复扫描、重试、撤销和手工确认的处理规则 |
| 验证 | 纯解析、前端状态转换与后端库存业务分别验证 |

合同未完成前不提供看似可执行的 Python／JS 片段。新增页面、组件或动作先通过正式模块交付，知识文稿不能直接添加能力。

不确定条码归属、字段缺失或状态不匹配时提示原因，不通过猜测商品、批次或数量继续业务。条码领域单独维护，不并入库存基础模块。需求案例见 [条码示例目录](examples/README.md)。
