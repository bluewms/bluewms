# 设备连接接口 AI 规范草案

hook：`device_protocol`。知识状态：`planned`。更新：2026-10-17。AI 运行合同和工具尚未定义／开放。

## 计划生成什么

在已注册设备适配器内生成受限的报文字段映射、状态解释或动作选择。TCP／HTTP／串口连接、鉴权、连接池、超时、重连及实际发指令由固定模块处理；不让生成代码直接创建连接或读取密钥。

## 合同落地前必须确认

| 项目 | 需要明确的内容 |
|---|---|
| 输入 | 协议／设备版本、脱敏报文、当前任务、允许动作与设备状态 |
| 输出 | 允许的结构化映射或已注册动作及参数；不允许任意地址或原始执行代码 |
| 状态 | 任务接收、执行中、完成、失败与未知状态的解释规则 |
| 幂等 | 请求／回报唯一标识，重复和乱序消息的处理 |
| 运行边界 | 长度／类型、枚举、单位、超时及重试规则由本地模块约束 |
| 验证 | 纯报文试算与模拟设备回归先行，再在授权环境验证真实设备 |

以上是设计要求，不是已经可用的输入 schema。未完成正式适配器和合同前，只维护需求与脱敏报文说明，不发布“可执行”案例。

生成代码不能改变设备连接权限，不能绕过任务状态机或库存校验。设备失联不能被解释为任务完成；未知回报应产生诊断，不能推断成功。需求案例见 [设备示例目录](examples/README.md)。
