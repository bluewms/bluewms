# WCS /4 生成配置规范
Wiki来源: domains/wcs/specification.md、configuration-guide.md及机器可读合同。以本地contract_schema为准, 代码在JSON AST沙箱执行, 不是任意Python。
无AI: 每条正数量、就绪移动行按原/目的位置直达, 使用人工WCS入出类型、设备类别、设备及任务类型; 自动创建须人工开关。无需AI配置或发布。入库须实际确认; 非入库有效预留不强制picked。
lines输入包含全部正数量候选, 不预先按AI条件过滤。request: phase、picking_id/state/company_id、operation(incoming/outgoing/internal)、人工wcs_type、all_confirmed(整单)、picking_source_id/picking_destination_id。candidate: line_id/line_key/carrier_key/route_key; product_id/product_code/lot_id/owner_id/uom_id; quantity/covered_quantity/available_quantity(行UoM); picked/stock_state; source_id/destination_id; stock_quantity/reserved_quantity(产品基础UoM); company_valid/storable/lot_ready/source_blocked/destination_blocked; carrier_all_picked(同载具, 非整单)/carrier_same_uom/carrier_quantity(异UoM为false); carrier_weight/volume及*_complete; package_max_weight/package_type_id。
每行恰一输出: {line_id:int,action:create|wait|exclude,quantity_basis:confirmed|reserved,quantity:number,group_key:string,source_ref:string,destination_ref:string,reason:string}。不能遗漏/重复行; quantity不超过available_quantity, wait/exclude为0。入库create必须confirmed; 非入库reserved无需picked, confirmed要求本行picked。wait待条件变化后重试; exclude只表示无需WCS, 库存仍正常处理, 固定指纹变更后豁免失效。等待行不能借排除验证。
group_key可line_key/carrier_key/route_key; 不同物理载具不能合成一计划。整载具须覆盖全部实际货物, 即使未满载也可按策略放行, 但不能把未计划货物随载具移动。满载不是all_picked: 可显式按重量/体积/同UoM数量阈值, 基础数据缺失complete=false应等待。原生package_max_weight是最大运输重量, 不是最小满载标准。
tasks输入: request.phase=tasks, positions/position_details(名称、站点与包含库存范围标志)、base_task、人工equipment(各授权任务类型/协议/能力)、lines与decisions字典; candidates是base_task。输出0..4任务, []表示整组等待。
任务精确字段: equipment_id:int、location_res_id:int、location_dest_id:int、source_ref/destination_ref:string、role:goods|empty_supply|empty_return、task_type:string、movement:primary|repeat|relay|empty、dependency_step:int、dependency_event:end|take|point|point_or_take、dependency_point/reason:string。步骤从1计数, 依赖0为无前置, 其余只能指更早步骤, 非end依赖需明确点位。非空任务须有goods, 第一goods保持人工主设备及行决策映射; 后goods须repeat(设备/任务类型/同数据端点相同)或relay(接前goods终点), 并依赖上一goods的end。空载具可明确配置点位或取货早释放, end兜底。
位置来源: line_source/line_destination、picking_source/picking_destination、source_parent/destination_parent、人工handoff。映射ID须对应声明来源, 物理首源/最终目的范围包含原库存位置; 多值行端点不能假取第一行。保存映射来源, 不自动改库存数量或位置; 未计划实际细点暂停核对。simulation支持; JSON散件/库区需人工能力确认; HIK/WES仍需载具, HIK范围可ZONE, WES仅既定端点; 真实同数据多程序须人工确认设备能力。无真实设备验收声明。
系统扣除非取消计划已覆盖数量, 同计划多任务不重复plan.line或库存。重扫只补未覆盖量; 在途载具等待, 同单已搬运载具新增货物要求核对。发送前复核当前库存/预留/冻结/载具货物及依赖。未知/失败不释放覆盖, 不伪造完成。
语法: 单变量赋值, JSON字面量, 已有字典字符串键读取, if/elif/else和条件表达式, and/or/not/比较/有界数字算术; 唯一循环for candidate in candidates, 唯一调用result.append(obj)。禁止import/def/class/lambda/while/try/推导式/属性/列表索引/字典写入或展开/get/len/dict/str/sort、ORM/网络/文件/SQL。代码32768字符、2000 AST节点、30000步骤, JSON输入262144字符, 最多200行/4任务, 文本512字符。2..20个{name,input,expected_result}精确试算需同时覆盖lines/tasks。纯解释器试算不替代业务回归, 草稿不等于发布。
