# 条码场景、异常处理与验收规划

日期：2026-10-20。状态：规划，以下预期尚未由新模块实现或测试通过。总体范围、模块、AI 边界及 UI 设计以[迁移方案](barcode-migration-20.md)为准。

## 已核对的易错点

| 依据 | 问题 | 实施要求 |
|---|---|---|
| 新盘库 `stock_inventory.py:action_start` | 账存可预填实盘，但尚未确认 | 首次有效扫码以 0 为基数，不能把账存当成已盘累计 |
| 新盘库 `stock_inventory_line.py` | 已盘、已记账及完整库存维度有现成约束 | 使用本单明细和原入口，保留序列号 0／1、公司及负责人约束 |
| 19 `barcode_model.js:splitBarcode` | 全局分隔规则先拆字符串并过滤空段 | 复合 QR 先完整解析，保留空段；不能把字段误变成多次扫码 |
| 19 `barcode_model.js:processBarcode` | 本地排队与临时重复保护不能证明刷新后幂等 | 服务端持久事件、结果及事务约束，刷新与重试复用事件 ID |
| 19 `stock_barcode.py` | 首页识别有 `limit=1`，部分位置扫描会建单 | 全候选消歧，首页位置只读，创建作业明确进入对应流程 |
| 19 `stock_barcode.py:save_barcode_data` | 接收任意模型、写字段与值的入口过于通用 | 固定模型、字段和注册业务动作；后端逐项复核 |
| 19 picking 模型与 20 实际容器 | 旧前端保留 `qty_done`／`reserved_uom_qty` 展示语义；20 实际明细为 `quantity`、`picked` 等 | 明确应作业、预留、已扫描、已保存、已验证各数量含义；不能把预留数量当成已经扫描 |
| 16 `view.py` 与 `WarehouseOperation` | 页由位置组合／源包裹／目的包裹形成 | 用稳定业务组标识，翻页不改变明细身份或扫描事件归属 |

源版本与许可记录见总体方案；本表是针对迁移风险的分析，不表示原模块全部场景均错误。

## 一次扫描的完整处理

1. 当前活动页面接收扫码枪、PDA、相机或手工输入；记录完整原文、采集来源、事件 ID 和当前上下文。浏览器只注册一条活动处理链。
2. 按终端配置剥离确切前／后缀，保留业务分隔符与 GS1 控制分隔符。默认不改大小写、不删除前导零、不把整串转数字。
3. 使用会话固定版本解析，取得结构化商品／数量／单位／追踪／位置字段；识别到复合格式但格式错误时停止，不能回退成普通商品码加 1。
4. 服务端在有权范围内解析候选，补齐商品、单位、批次、包裹、货主、位置、单据等身份；不唯一则进入明确选择／补扫步骤。
5. 已发布策略在已授权能力内选择下一动作；固定服务复核最新单据、数量、追踪、库存规则和状态版本。
6. 对本次动作进行同事务保存，持久化事件及结果；需要补扫的信息不先增加数量。失败时本次不留下部分修改。
7. 前端展示服务端确认的增量、总数、位置及下一提示；采集提示与业务成功提示分开，待确认数量不冒充已保存数量。

网络超时只表示结果未知：先按原事件 ID 查询／重试，不能生造一个新事件。涉及 WCS／ERP 的后续传输通过既有队列执行，避免重发扫描动作。

## 第一版建议默认规则

以下为开发默认建议；用户明确的累计、四入口、批次作业和分页偏好已确认。将来客户调整流程通过基础授权和已发布策略处理。

| 项目 | 默认处理 |
|---|---|
| 普通商品码 | 一次真实扫描增加一个库存基本单位；有包装单位码时按已配置换算 |
| QR 数量 | 由明确规则声明为本次增量；QR 表示总数必须使用单独声明的总数模式，禁止自动猜测 |
| QR 必填字段 | 声明必填的数量／商品缺失则拒绝整次；只提取商品的规则可以使用普通增量 |
| QR 多种格式 | 用明确前缀／结构等条件选择规则；多条规则冲突须报错，不以排列先后取首个 |
| 产品重码 | 当前允许范围仍有多候选则选择；不默认第一个，也不自动全库建产品 |
| 位置码与商品码重合 | 当前要求的扫描步骤参与识别；仍有歧义则让用户选择类型 |
| 满量／超量 | 达到允许量后提示本组已满；超量需基础授权和策略明确允许，不能因重复扫描自动放开 |
| 同商品多行 | 先按位置／追踪／包裹及明确组上下文匹配；跨单分摊须明确规则 |
| 批次／序列号 | 必需信息未齐前暂存解析草稿，不先加数量；错误商品关系或重复唯一序列号拒绝 |
| 新产品／批次／包裹 | 不自动创建；只有基础授权且固定服务支持的创建动作可进入明确流程 |
| 首页扫描位置 | 查询详情；进入作业后的扫描位置用于当前作业上下文 |
| 盘库未盘行 | 不自动当作 0；必须实际扫描、手工设总数或明确确认 0 |
| 纠错 | 提供最近事件与明确的纠正／撤销动作；未记账且版本未冲突时处理并留记录 |
| 自动完成 | 可按策略建议下一组；整单验证由注册动作进入，保留原生警告、欠单及权限流程 |

没有具体 ERP、包装单位或追踪规则时，采用上述保守业务默认，不虚构客户专属格式。第一版自定义分隔 QR 一次代表一个商品和其相关字段；一张 QR 含多个商品清单另列后续需求，不能误作为多枪逐段执行。

## 必测异常矩阵

### 采集与编码

| ID | 场景 | 应有结果 |
|---|---|---|
| C01 | 同一商品枪扫两次 | 两个真实事件，正常加 2；不按字符串全局去重 |
| C02 | 相机同一画面连续多帧识别 | 单次确认只计一次；移开／重新触发后才成为下一次扫描 |
| C03 | 扫码枪 CR、LF、CRLF、Tab 或设备前缀 | 只按已配置边界收成一次输入，不多触发一次提交或按钮 |
| C04 | 一次 QR 内含 `#`、空字段或控制字符 | 按声明格式保留字段边界；不误拆商品事件 |
| C05 | 编码 `000123`、字母大小写、全角字符 | 精确匹配；不丢前导零，不擅自改写为另一个产品 |
| C06 | 手工输入框、数量弹窗正在编辑 | 手工编辑不会被全局扫码监听吃掉；确认后恢复扫描焦点 |
| C07 | 连续高速扫描、切页、弹窗、浏览器后台 | 有序排队，只由活动页面接收一次；明确展示暂停／等待状态 |
| C08 | 无相机权限、扫码能力缺失、设备不支持 | 明确提示并可用扫码枪或手工输入；实际 PDA 能力单独验收 |
| C09 | 特长输入、异常控制字符、HTML 文本 | 有长度及执行限制；以纯文本展示，不执行脚本或页面跳转 |
| C10 | EAN／GS1、FNC1、可变长批次或序列号 | 复用适用原生解析；校验实际样本，不用 `#` 逻辑替代 GS1 |

### QR、数量与追踪

| ID | 场景 | 应有结果 |
|---|---|---|
| Q01 | `HDR#VENDOR#SKU001#LOT88#12#END`，只声明商品和数量 | 一次 SKU001 加 12；不先加 1；不自动认 LOT88 为批次 |
| Q02 | `HDR##SKU001#LOT88#12#END` | 空段保留，商品仍在第 2／3 个 `#` 之间 |
| Q03 | 缺少第 5 个 `#`、空商品或声明必填数量为空 | 全次拒绝，原数量、追踪与位置不变 |
| Q04 | 数量为非数字、负值、NaN、Infinity、超大值 | 明确拒绝，不能隐式变为 0／1 或溢出 |
| Q05 | 小数、箱／件、重量单位、不同单位类别 | 声明单位且按配置换算和舍入；不兼容单位拒绝，显示实际基本单位数量 |
| Q06 | 包装码已带换算量，QR 又带数量 | 明确唯一数量来源及语义；不能对“已是件数”的值再乘一遍装箱数 |
| Q07 | QR 同含商品、批次、数量但批次属于另一商品 | 本次全部拒绝；不先创建行或增加数量 |
| Q08 | 序列号商品数量 12 或相同序列号重复扫 | 拒绝；盘库序列号行仍只允许 0／1 |
| Q09 | 不同产品批次同名、同商品分散多个库位／货主 | 补齐维度后唯一匹配；不按名称或第一行猜测 |
| Q10 | 规则格式已匹配但解析失败；多规则同时匹配 | 明确规则错误／冲突，不能退回普通商品码计数 |

数量为 0 的自定义增量扫描默认拒绝；盘库“确认实盘为 0”通过明确总数动作执行。纠错走对应动作，不能用负数 QR 绕过数量约束。有效小数按产品单位能力校验，首版不把不明确的逗号猜成小数点或千位符。

### 作业、分页与包裹

| ID | 场景 | 应有结果 |
|---|---|---|
| O01 | 同商品处于不同来源／目的位置组合 | 当前明确组可参与匹配；不明确时要求位置／组选择 |
| O02 | 扫描排队时用户翻到下一页 | 已采集事件保留原上下文，不写到翻页后的当前组 |
| O03 | 当前组扫完、再扫同商品 | 根据剩余候选定位或提示已满，不自动记到任意另一组 |
| O04 | 批次内两张单同商品，QR 数量超过第一张余量 | 有分摊规则时逐行复核且合计一致；否则选择，不静默截断或越界 |
| O05 | 批次被移除单据、ERP 修改行、预留或单位变化 | 后端识别版本／归属变化，刷新并核对，不用旧缓存强写 |
| O06 | 整包扫描后再扫包内产品／父子包裹 | 明确整包与逐件模式，已覆盖的同一货物不能双算；校验包裹实际位置与内容版本 |
| O07 | 源包裹与目标包裹编码相同或相互嵌套 | 按当前动作与实际包裹规则复核，不造成自包含或错误搬移 |
| O08 | 加入额外商品、新建批次、装箱 | 人工能力授权、策略和实际库存规则全部满足才执行 |
| O09 | 原生验证返回欠单／追踪／警告对话框 | 正确呈现并处理返回动作；未真正 done 不显示整单完成 |
| O10 | 操作中单据被取消、完成或被 WCS 接管执行 | 重查状态，按现有 WCS／库存允许入口处理，不竞争修改或重复记账 |

页目录依据稳定组键保留定位。完成后明细顺序变化不应把操作员突然带到另一组；如需自动前进，等待本次确认后再切到确定的下一未完成组。

### 盘库

| ID | 场景 | 应有结果 |
|---|---|---|
| I01 | 账存预填 100、未盘，首次扫 1 | 实盘 1、已盘；账存仍为 100 |
| I02 | I01 后再扫 1，再手工设总数 8，再扫 1 | 实盘依次为 2、8、9，保留每次旧／新值 |
| I03 | 翻页、刷新、退出后恢复已盘行 | 保留已确认数量；恢复或继续，不重复计数或清零 |
| I04 | 未盘行与明确盘为 0 | 分别显示；完成前按盘库核心要求确认，不批量猜成零 |
| I05 | 扫到本单范围之外或缺少批次／包裹／货主 | 拒绝或要求补扫；普通盘点员不能自动新增维度 |
| I06 | 管理员补本范围内的新库存行 | 按核心权限和维度建立后再盘；扫码不直接建 quant 或库存移动 |
| I07 | 明细已应用、单据已完成／取消 | 不能继续计数或撤销；正确显示只读和原因 |
| I08 | 刷新账存使实盘重新待确认；扫描中账存／单位变化 | 旧会话停止并重新核对，保留核心冲突检查 |
| I09 | 两人重复盘同一实物区域、同一账号开两台 PDA | 首版通过单据写会话占用与交接阻止默认双写；不把同一批实物误当两批累计 |
| I10 | 盘库只扫包裹码 | 仅定位对应明细，不自动把账存内容变成实盘确认 |

### 网络、并发与外部系统

| ID | 场景 | 应有结果 |
|---|---|---|
| N01 | 服务端已保存但响应丢失 | 原事件重试返回原结果；数量只更新一次 |
| N02 | 同事件 ID 改换商品或数量重发 | 拒绝内容冲突，不复用旧授权或重复执行 |
| N03 | 页面重载／浏览器崩溃时存在待确认事件 | 先查事件结果并恢复；无法确认时明确待处理，不当成新扫描 |
| N04 | 手工改总数期间另一个已授权动作修改数量 | 旧版本总数提交被拒绝并刷新，不覆盖新值 |
| N05 | 扫位置失败，后续商品已排入队列 | 暂停依赖事件，纠正后明确继续，不沿用错误位置 |
| N06 | 保存扫码量成功、请求 WCS 失败 | 显示“数量已保存，WCS 待重试”；仅重试请求，不重加数量 |
| N07 | 双击 WCS／验证按钮，回调或 ERP 消息重复 | 复用既有幂等及状态机；不能重复任务或库存记账 |
| N08 | 库存验证成功、ERP 暂时不可用 | 库存结果保持真实已完成；ERP 事件队列显示待发送／失败并可核对 |
| N09 | 切公司、登出、权限撤回、写会话被接管 | 旧会话不能写；待确认数据隔离，不跨用户／公司继续重放 |
| N10 | AI 策略中途发布／回滚、超限、失效或执行失败 | 原会话版本固定；失败停在明确步骤，不静默更换规则或降级计数 |

## 会话、恢复与诊断

会话拟保存：真实业务单据、公司、用户、解析／流程版本、组键、已确认扫描步骤、占用及状态版本。事件拟保存：事件 ID、内容摘要、来源、目标行、动作、基本单位增量／总数、旧／新值、策略版本、结果和纠正关联；具体模型字段在合同阶段冻结。

事件确认和相关数量修改同事务保存。追踪草稿中待补扫的商品／批次／数量绑定同一组有效上下文；切换单据或明确取消时清除，不能把上一商品的批次套给下一商品。跨页或跨商品带入的追踪状态只有规则明确且业务维度适用时才允许继续。

首版承诺在线和短时故障恢复；服务不可达时暂停业务计数并提示。若保留少量已采集待确认事件作恢复使用，其用户／公司／会话、ID 和内容须可核对，不能依赖“又扫一次”恢复，不能宣称支持完整离线作业。服务端已确认事件是恢复依据，前端缓存和小计不是库存权威。

操作员可查看最近事件的“待确认／已保存／被拒绝／已纠正”和具体原因。原码可能含客户信息，只保存诊断所需内容并限制访问；云端 AI 草稿仅使用必要的脱敏样本，不逐枪发送业务数据。原码和 AI 提示均作普通文本展示，页面与流程不能从二维码中执行脚本、任意方法或命令。

纠正已保存的最近事件必须检查行的新版本、后续事件和记账状态；存在后续修改时采用明确的数量纠正流程，不恢复整个旧快照。已验证的库存移动走原生退回／后续单据流程，条码撤销不逆转已记账历史。

## 性能与现场核对

- 使用 10／100／1000 行、多个位置／包裹组、同商品多行的数据测量首次打开、切组、候选查找、连续扫码队列和保存耗时。查询按当前单据／仓库及权限限定并分页，不照搬旧代码读取全部包裹或预加载全库产品。
- 性能验收同时核对采集数、已确认事件数及最终数量；快速扫描可以排队，不能静默丢码、合并真实重复码或出现界面总数与后端不一致。具体吞吐及延迟标准依据实际 PDA 和仓库网络测量后记录，不在规划中虚报数值。
- 用真实标签核对键盘布局、中文输入法、前后缀、休眠唤醒、浏览器返回、横竖屏、扫描焦点和响声；本地演示页面通过不等于客户 PDA 已验收。声音／震动不可用时仍有清楚的视觉结果，错误不能只靠一声提示。
- 编码恰好与操作命令重名时，需要命令识别和业务识别消歧；商品／QR 原文不能自动触发验证、装箱、取消或页面导航。最终动作仍受当前步骤与能力授权约束。
