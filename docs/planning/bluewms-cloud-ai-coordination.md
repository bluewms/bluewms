# BlueWMS 云端知识与本地 AI 工具协作方案

更新：2026-10-16。现行依据：[云端知识、Tencent 配置与 AI 工作流](../wiki/README.md)。原云端任务网关方案保留为后续选项，不作为已实现流程。

## 当前分工

- `muk_ai`／`muk_mcp`：本地聊天、消息与工具说明组装、问答、业务工具调度和结果反馈。当前业务工具循环由 MuK 主持。
- `blue_ai_client`：Chat Completions provider、每用户 Key／Agent、稳定会话、资产绑定、三个草稿工具；后续增加受限云端只读检索与按 hook 选 Task。
- TencentDB-Agent-Memory：云端通用示例、项目知识、Skill、个人记忆及共享权限。模型由配置的服务提供，记忆平台不等同于模型训练。
- 本地资产与业务模块：真实合同、草稿及正式代码、本次测试、人工发布、版本固定、回滚和确定性执行。

不另建本地 `blue_ai_memory` 或作为私有知识库的 `blue_ai_skills`。已安装 `muk_ai_skills` 保留框架用途；它不是 Tencent Wiki 的远程读取接口，也不承担云端私有知识正文镜像。

## 团队和身份

一个 `odooAI` 团队，用户各自的 Agent 与业务用户 Key，批准的 Wiki／Skill 团队共享并显式绑定。五类入口用 Task 分类，个人记忆私有；Task 不作客户权限隔离。

五个业务 Task 已在云端建立：上架策略、ERP接口、WCS生成策略、设备连接接口、条码扫描策略。现有客户端仍固定初始化“日常任务”，该兼容 Task 保留。自动按绑定资产 hook 路由是待开发项，不能写成已切换。

## 当前正常闭环

1. 从资产页面打开聊天，服务端固定资产、草稿摘要和正式基础版本。
2. MuK 将用户需求、工作流程提示、允许工具和历史反馈发送到云端代理，代理按实际用户身份初始化。
3. AI 调用 `blue_read_code_asset`；本机返回当前草稿、测试、需求、接口版本及摘要。当前还返回本地示例，属于待迁移的兼容实现。
4. 模型调用 `blue_submit_code_draft` 保存草稿，服务器检查权限、内容摘要、基础版本和受限语法。
5. `blue_validate_code_draft` 在本地执行测试，错误反馈给模型修复；用户在资产页面审阅并发布。
6. 日常业务执行本地已发布代码，知识服务故障不会要求重新请求模型。

当前读取工具的 contract 是版本标识，尚非完整机器可读字段／语法／输出规范。发布与实际执行成功不能由聊天文本推断。

## 云端知识的目标接入

已批准示例和说明统一在云端按 Odoo／模块／hook／合同版本维护。生成前读取准确正文、来源、版本和批准状态，不能只凭标题或语义摘要。

当前代理通用说明依赖客户端 Bash/curl，而 Odoo 使用服务端固定 Skill bridge 读取批准上架知识，把正文返回资产工具结果。上传／绑定成功和模型真正取得全文分别验证，禁止向模型开放任意 URL、文件、ORM 或 shell。直接 Wiki 检索及新增资源按需扩展。

上架已实现只读知识接入、完整合同、新会话 Task 路由和停止本地示例回传；旧运行定义、当前／正式代码及本次验证用例继续本地保存。后续按具体合同接入 ERP、WCS、设备和条码，见 [本轮交付](../migrations/putaway-cloud-knowledge-20.md)。

Git 保存公开工程文档和知识来源；云端作为 AI 的知识发布／检索入口。私人聊天、密码和管理凭据不进入公开 Git 或共享知识。错误推断先纠正源记忆，再修正画像与场景，并核验新会话。

## 后续云端任务网关选项

项目授权、套餐、用量账本、后台生成任务及签名交付接口需要另行实现；当前 Memory 业务用户 Key 不等同于商业项目授权。不能将 MuK 参考费用当作真实账单。

如将来由云端主持后台生成，先明确幂等、任务状态、验证反馈、取消和失败恢复；同一流程只能有一个业务工具循环主导方，不能和当前 MuK 循环重复执行。原拟议生成任务 API 和 Responses 适配均属于方案研究，不是现场现成功能。
