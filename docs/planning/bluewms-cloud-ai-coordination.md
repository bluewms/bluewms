# BlueWMS 云端 AI 生成与本地执行协作方案

日期：2026-10-13。状态：云端任务网关为后续建议方案；首期代理接入已实施。
> 2026-10-13 实施更新：首期已采用用户指定的腾讯 CodeBuddy Chat Completions 代理。团队固定 odooAI，任务固定“日常任务”，Agent/业务用户 Key 按 Odoo 用户配置；移除剩余额度展示。当前由 MuK 主持本地工具循环，云端代理负责记忆/技能注入和模型转发。下文宝蓝云端任务网关属于后续方案，不代表本次已开发。实际交付见 blue-ai-client-module-plan.md 和模块 README。


## 产品边界

客户本地只配置宝蓝服务地址与宝蓝客户 API Key。腾讯 Memory Key 和模型厂商 Key 保留在宝蓝云端。核心知识、批准的模板、技能正文、生成策略与模型调用统一由云端管理。

TencentDB Agent Memory 提供记忆与技能管理；模型推理由另行配置的模型服务承担。官方仓库 MemoryProxy 可作为参考，但开发分支能力不等于现有托管实例能力，需核验部署版本及接口。

## 分工

- MuK：本地聊天、流式展示、业务记录上下文与审批界面。
- blue_ai_client：宝蓝云端 provider、身份映射、请求封装、生成结果与草稿接口衔接；沿用既有约定，不新增 blue_ai_memory。
- 宝蓝云端网关：客户鉴权、套餐和额度、云端规则/技能选择、Tencent 召回、模型调用、任务状态、审计和计量。
- Tencent：团队知识与客户记忆；正式规则与批准模板有明确版本，不由聊天记忆自动覆盖。
- 本地资产系统：当前代码和接口契约、草稿、业务试算、验证、发布、版本固定与回滚，按当前 Odoo 用户权限执行。

## 单次闭环

1. 用户在代码资产页面提出修改需求，本地读取实际代码、基础版本、接口契约、允许修改范围与必要样例。
2. 本地调用宝蓝云端生成入口。云端从凭据解析客户身份，校验项目/实例/功能授权，不能信任请求自报的租户 ID。
3. 云端按入口与接口版本选择明确的规则/技能版本，再召回辅助知识、客户记忆与批准示例，调用模型生成候选代码和测试。
4. 返回 task_id、目标资产、base_version、代码、测试、规则/技能/模板版本与生成说明；必要时返回追问。
5. 本地核对目标和基础版本，调用既有 action_submit_draft 草稿接口，展示差异并执行本地验证/试算。
6. 本地把校验失败和最小必要上下文返回同一云端任务，云端修复；限制修复轮次与成本。
7. 授权用户发布。本地回传最终成功/失败结果，云端保存任务准确产物和经审核的经验。

不需要云端直连客户数据库，也不需要浏览器模拟点击代码字段。已有本地生成/验证/发布接口需通过实际适配完成闭环；当前尚未完成 Tencent 联调。

## 知识与记忆治理

批准规则、技能和模板作为带版本的正式资产管理，生成时按兼容版本明确加载；不能完全依赖语义召回选取强制约束。个人偏好、项目经验和历史纠错进入记忆。客户数据按租户/项目隔离，正式代码全文另存准确资产与恢复材料，不能用摘要记忆代替。

MuK 本地只保留入口描述和执行接口，不复制云端核心技能正文。同一生成流程只设一个主导方；本方案由云端主持代码生成循环，MuK 承担聊天与本地动作。

## API 与授权建议

以下是拟定的宝蓝接口，并非腾讯现有接口：生成任务、提交验证结果、查询任务状态、查询用量与授权。HTTP/SSE 实现流式进度；请求使用幂等键，按 task_id 对账。请求包含协议版本、入口、资产 ID、基础版本和必要上下文；租户身份从服务端凭据解析。

宝蓝客户 Key 支持按项目/实例/功能绑定、额度、限流、轮换与撤销。云端实际检查资格和额度；本地状态用于展示。客户订阅云端生成、知识、模板及维护能力；已发布代码在本地执行不必每次消耗 AI 额度。生成用量与模型 token 成本分别记账，重试、失败和系统修复的扣费规则需在上线前明确。

## 协议选择与实施顺序

2026-10-13 源码复核：Tencent feat/server_team 提交 badbd2179d06f4e0e1f2133bd3482880beab8a02 已支持 Responses，README 协议列表不完整。server.ts 明确注册 /codex/:spaceId/v1/responses 与 /codex/:spaceId/responses，codex runner 实现会话初始化、资产注入、Responses SSE 和归档；无需因协议原因把 MuK 改为 Chat Completions。

实际不兼容点：MuK 系统消息没有显式 type=message，而代理注入函数对此有强校验；MuK 未发送代理识别的稳定 session-id；Codex 初始化表单使用 request_user_input 工具；部分技能交付依赖客户端 shell/curl 执行工具。旧 /proxy/:spaceId 路径关闭记忆/技能注入，不能用来验证知识接入。

推荐 blue_ai_client 新增独立宝蓝 provider，复用 MuK OpenAI Responses 编解码，补充消息规范化与稳定会话元数据。云端宝蓝网关负责客户鉴权/计量、自动身份绑定，以及服务端读取知识/技能正文，避免要求 Odoo 执行 Codex 专属表单或 shell 工具。腾讯上游保留原始代码；若必须复用 MemoryProxy 完整编排，则新增 Odoo 专用适配器与明确 Responses 路由，不直接将 Odoo 长期伪装成 Codex。所查源码支持不代表用户云端部署版本已支持，需获取镜像/commit 再联调。

1. 先用上架策略一个入口：页面需求 → 云端规则/技能/模型 → 本地草稿 → 试算验证 → 发布/回滚。
2. 完成客户 Key、额度与任务账本；验证租户隔离、撤销、重复请求、版本冲突、修复与断线恢复。
3. 复用协议扩展到其余业务入口。
4. 企业微信作为同一云端服务的另一入口，再接账号映射和审批交互。

验收：云端无授权无法生成；客户拿不到腾讯/模型凭据；错误代码无法发布；旧版本产物不能覆盖新修改；重试不重复扣费；云端故障不阻断已有正式业务代码；生成结果可追溯规则和技能版本。
