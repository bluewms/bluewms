# 设备连接接口 AI 规划

日期：2026-10-18。状态：使用方式及 TUSK 首期范围已确认，本文为实施方案，尚未修改业务代码或发布设备知识。现状以 Odoo 20 `c146d68` 和 Odoo 19 `bluewms19` 工作区的 `7d77ae7` 为参考。

## 已确认的使用方式

1. 继续使用 **WCS → 设备类别** 页面。人工新建类别，再让 AI 生成该类别的接口草稿，不为每个厂家新增模块。
2. 接口地址、认证密钥和回调凭据全部放在类别，所属设备统一使用，不增加每台设备的连接覆盖选项。
3. 去掉类别页中直接新增设备的明细入口；设备统一从 **WCS → 设备** 新增并选择类别，保留模型关联和数量统计。
4. 第一阶段只做任务下发、下发响应解析、完成回调，不包含取消、关闭、解绑和位置查询。
5. 先用 TUSK 跑通，再逐步整理 M4、Mita、Modula。第一阶段按这些旧模块现有的 HTTP／JSON 通信形式设计。
6. 用户确认 TUSK `feedbackTask` 只在任务最终完成时回调；按旧版方式兼容，不要求设备新增认证请求头。

## 现有代码的核对结果

Odoo 20 的 `blue_wcs_base` 已有类别、设备、持久发送队列、HTTP 发送和认证回调；`blue_wcs_wes` 提供 WES 扩展。当前适配方式是代码内固定的 simulation／HIK／JSON／WES。类别中的连接参数优先，设备还保留历史连接字段，因此新接口需要明确只使用类别参数。

设备 AI 入口和共享 Task 已存在，但设备生成合同尚未开放，当前设备 Wiki 仍为 planned，不能把已有的知识聊天当成已能生成并执行协议。

| 旧模块 | 可以提取的协议资料 | 需要单独处理的边界 |
|---|---|---|
| `blue_wcs_tusk` | `/rpc/createTask`；taskId、targets、configId；msg=success；feedbackTask 回调 | 用户确认回调表示最终完成，按旧版无 Token 方式兼容；取消接口后续再做 |
| `blue_wcs_m4` | entityName／entityValue 包装、任务与位置字段、专用认证头和反馈 | 旧回调直接修改任务及库存行目的位置，不能作为普通报文转换照搬 |
| `blue_wcs_mita` | 容器、站点、库区、明细及入出库报文；完成和位置反馈 | 创建业务任务、关闭、解绑及位置查询分别归类，首阶段不开放 |
| `blue_wcs_modula` | 订单头／订单行、数量、物料和 XY 位置映射、完成反馈 | 特有物料及位置字段要有准确来源，不能假定 Odoo 20 已提供全部字段 |
| `blue_wcs_mita_barcode` | 条码确认后触发 Mita 的业务案例 | 属于条码／WCS 创建联动，不混入设备通信合同 |

旧代码只作为协议来源，不整套复制成运行时脚本。整理时保留源模块、文件、提交及适用版本，移除真实地址、密钥和客户数据；任务创建和库存修改仍由正式业务模块负责。

### 四类旧回调的实际差异

以下四类控制器均为公开 POST、`csrf=False`，函数内未校验 Token、签名或来源 IP。不能因为有任务号就称为已通过身份认证。

| 模块 | 回调定位／完成条件 | 旧版认证 |
|---|---|---|
| TUSK | taskId 定位；targetPoint 为回报点位；用户确认只在最终完成时回调 | 无 |
| M4 | container 匹配进行中任务，status=unloaded 后完成；虽收到 id，旧逻辑没有按 id 精确定位 | 无 |
| Mita | details 数组逐条按 taskNo 定位，taskStatus=FINISHED 后完成；另有包裹位置回报 | 无 |
| Modula | DATA.EXP_ORDINI_RIGHE_STO 数组逐条按 STO_HOSTINF 定位后完成 | 无 |

第一阶段按用户要求保留 TUSK 的旧回调路径 `/api/blue_wcs_tusk/feedbackTask`、JSON 报文、无附加 Token 及 `{code: 200, msg: success}` 成功应答。仍由固定服务检查任务所属类别／设备／公司、已下发状态、回报点位和重复事件，生成代码不能扩大查询或写入范围。任务及报文校验不等于来源身份认证。现有 HIK／WES 等路由的 Token 校验不全局关闭。

M4 的容器定位与库存位置回写、Mita 的批量反馈、Modula 的逐行完成含义在各自落地时再核实，不把 TUSK 的最终完成语义套给所有设备。

## 一次建设通用能力

建议新增一个通用模块 `blue_wcs_protocol`，负责设备协议合同、类别绑定、报文试算和发送／回调接入。沿用 `blue_config_asset` 的草稿、验证、不可变版本、发布和回滚流程，扩展已有 `blue_ai_client` 设备入口。后续常规 HTTP 厂商接口表现为新的设备类别和发布资产，不再增加厂家模块或固定厂家枚举。

现有 HIK／WES 等适配保持兼容，新类别选择可编辑 HTTP 接口。需要新增传输形式或现有执行器没有的认证算法时，再补通用能力；不把任意网络调用、模块安装或新增数据库字段交给生成代码。

类别页建议包含：

- 基本信息与类别级连接参数；凭据按权限隐藏，不发给 AI。
- 接口说明、允许的操作／相对路径和必要业务参数。
- 草稿代码、试算输入／输出、验证结果、当前发布版本及历史版本。
- AI 生成／修改、试算、验证、发布、回滚按钮，AI 沿用现有可放大浮窗。
- 设备数量及查看入口；设备的任务模板、厂商设备编码等实例信息仍在设备页维护。

发布只作用于选定类别，不自动创建类别、设备或其他配置。

## 设备专用合同

拟使用独立的 `device_protocol/1`，不复用 WCS 创建合同 `/4`。第一阶段分为三个纯数据阶段：

| 阶段 | 输入 | 输出 |
|---|---|---|
| 生成下发报文 | 已确定的任务、起终点、设备模板、载具／货物及批准的非秘密参数 | 允许操作及其 JSON 请求体 |
| 解释下发响应 | HTTP 状态、受限响应正文及原任务标识 | 已接受、明确拒绝或结果未知，以及必要的厂商关联标识 |
| 解释设备回调 | 按人工配置接入的回调、受限报文及任务固定版本的上下文；TUSK 采用旧版兼容模式 | 有界的标准事件列表、任务标识、事件标识、点位和有界应答内容 |

AI 编写报文转换与解释逻辑；固定执行器负责地址选择、凭据注入、通信、超时、人工配置的认证／兼容接入方式、任务关联校验及状态迁移。AI 不能修改认证方式或动态注册任意 Odoo 路由。人工试算仅处理报文，不发真实任务；真实连接测试单独操作并明确目标。

任务在创建时固定协议发布版本；下发与后续回调必须按同一版本解释，避免类别发布新代码后改变在途任务。回调任务定位字段是兼容约束，存在在途任务时不能随新草稿任意更改。配置变更不能静默将旧任务发往另一连接目标。

重复回报只处理一次；未知或中断结果进入待核对，不按成功处理或盲目重发。设备事件走现有 WCS 状态机和库存核对流程，生成代码不直接完成库存单据或修改库存位置。

## 云端知识安排

继续使用已有 **设备连接接口** Task 和 **Odoo-AI-设备接口** Wiki，不创建额外 Task，也不恢复 Skill bridge。本地只保存实际草稿、正式代码和准确合同，维护来源仍是 `docs/wiki/`，知识发布到云端供检索。

在现有 `docs/wiki/domains/equipment/` 下按职责整理：

| 文件／目录 | 内容 |
|---|---|
| `specification.md` | 当前实际开放的设备合同、三个阶段及字段规范 |
| `configuration-guide.md` | 类别／设备职责、参数、AI、试算与发布步骤 |
| `reference/legacy-interfaces.md` | 四类旧接口的来源和差异，明确哪些尚未支持 |
| `examples/tusk-submit-callback.md` | 首个按新合同验证通过的 TUSK 报文、代码及预期结果 |
| 后续 M4／Mita／Modula 独立案例 | 各自的协议差异；转换为实际合同并通过测试后再作为可执行示例发布 |

通用生成规则仍放通用 Wiki。设备合同、客户端工具和准确示例完成后，才更新设备库的合同、批准页、摘要和生成状态；未实现的厂商动作保持参考／planned，不能因上传了旧代码就标为可执行。

## 实施和验收顺序

1. 按已确认的使用方式及旧版 TUSK 回调，冻结首期 HTTP／JSON 合同和输入／输出样例。
2. 建立一次性的通用协议能力，调整设备类别页，接已有资产流程与 AI 设备入口。
3. 用 TUSK 完成编辑—纯报文试算—验证—人工发布—模拟执行／回调—回滚，覆盖重复、错误、未知及版本变化。
4. 在隔离数据库核对公司权限、类别连接、在途版本、发送幂等和库存不重复记账；既有上架／WCS 生成回归通过后再升级主库。
5. 发布经核对的设备 Wiki，验证实际设备 Task、原生检索和完整读页及 AI 保存／验证草稿。
6. 有明确测试环境和厂商协议后进行真实设备验收，再逐个补齐其他厂家案例和后续动作。

此规划不代表设备 AI 合同或真实设备接入已经完成；不因代码已生成或模拟通过，就标记真实设备已验收。
