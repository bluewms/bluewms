# BlueWMS20 开发计划

更新：2026-10-20。本文以已交付源码和验收记录区分当前能力与后续计划，不用早期调查稿决定现场行为。模块与依赖见[架构](../module-architecture.md)。

## 产品目标与工程基线

基于 Odoo 20 社区版、MuK 20 和宝蓝模块，形成可供人工仓、自动化仓及混合作业使用的 WMS。客户通过业务页面提出需求，AI 从批准 Wiki 和本地真实合同生成受限增强代码，经验证及人工发布后在本地确定性执行。结构扩展仍由正式模块交付。

开发运行于 Docker，所有 addon 直接放在 `bluewms` 根目录并挂载到 `/mnt/extra-addons`；PostgreSQL 16 系列及 Odoo 镜像以[部署清单](../../docker/deployment-lock.json)为准。相邻官方源码是参考仓库。新环境按[Docker 说明](../../docker/README.md)建立自己的私有配置、凭据和数据卷。

迁移完成后的首个产品正式标签计划为 `V2.0.0`，不等于当前已发布；addon 的 `20.0.x.x.x` 版本独立管理。

## 已交付

| 能力 | 当前成果与验收入口 |
|---|---|
| 平台与界面 | MuK Web、AI／MCP 及主题依赖已锁定；库存与品牌界面分离 |
| 库存基础 | 库位、容量、包裹与汇总迁入 `blue_stock_base`，见[库存基础](../migrations/blue-stock-20.md) |
| 库存硬约束 | 独立 `blue_stock_rules`，非负库存、冻结和禁止入库，见[规则说明](../migrations/stock-rules-20.md) |
| 人工盘点 | 独立盘点单、范围与实盘、原生调整和不可变历史；独立 ERP 关联桥接，见[盘点迁移](../migrations/stock-inventory-20.md) |
| 上架增强 | 原生规则选择增强场景，系统设置优先、整托不拆、同单／批次偏好或限制，见[上架说明](../migrations/putaway-policy-20.md) |
| 合同与资产 | 受限解释器、草稿／试算／不可变版本／发布／回滚，代码和准确测试保存在数据库 |
| WCS | 基础逐行创建、/4 两阶段增强、repeat/relay、数量覆盖、持久发送和认证回调，见[WCS 说明](../migrations/wcs-20.md) |
| ERP 接口首版 | 新建四类接口、/1 受限映射、原生建单与欠单、完成事件／盘点差异快照、持久队列及核对，见[ERP 交付](../migrations/erp-interface-20.md)；新 Wiki 与网关待独立发布 |
| 原生云端知识 | 通用＋五类 Wiki，按当前身份、合同、批准页和摘要读取；无本地示例兜底 |
| 五类 Task | 上架、WCS、ERP、设备、条码分别使用真实同名 Task；普通聊天使用日常任务 |
| AI 草稿闭环 | 上架、WCS /4 及设备 /1 草稿；设备类别、TUSK 与位置回写见[设备交付](../migrations/device-protocol-20.md)，其他见[原生 Wiki 验收](../migrations/native-wiki-runtime-20.md)；ERP /1 本地草稿工具已接入，真实联网生成待云端 ERP 知识及网关独立发布；条码 /1 本地合同与资产已在隔离库验证,主库安装及云端发布待完成 |

源码存在、模块已安装、模型联调通过和真实设备验收是不同状态。现有 HIK／JSON 及统一 HTTP 接口与模拟测试不代表全部厂商现场已经验收；WES 专用模块已退役，协议保留在设备 Wiki，旧 19 客户数据库和在途任务没有因本仓库迁移而自动升级。

## 后续顺序与验收出口

| 阶段 | 需要完成的工作 | 出口 |
|---|---|---|
| 1. 巩固现有闭环 | 在另一开发机按同一 PR 基线升级；补真实作业和设备现场验证；形成可重复安装／恢复材料 | 代码、数据库、附件、人工参数和固定版本可核对，异常能诊断恢复 |
| 2. ERP 接口现场适配 | /1 已实现推送建单、部分完成及盘点差异；后续发布 ERP 知识和网关、进行真实模型与 ERP 联调；再按需增加轮询、动态认证、单据变更及取消 | 准确报文、幂等与核对、现场端到端验收；首版模拟回归不能代替真实 ERP 验收 |
| 3. 扩展设备协议 | /1 类别级 HTTP 与 TUSK 先行；后续补 M4／Mita／Modula 的准确字段、批量回调及经授权动作，新增传输补通用能力 | 各厂家准确回归、幂等及真实现场验收；旧参考资料不能代替已完成适配 |
| 4. 条码增强 | 四模块初版、四入口、分组分页、盘库扫码与 AI /1 已实现,正在隔离库和浏览器验证;见[迁移方案](barcode-migration-20.md)、[50 个场景](barcode-scenarios-20.md)及[进度](../migrations/barcode-20-progress.md) | 主库安装、云端知识独立发布及实际 PDA 验收分别完成;隔离库成功不等于全部现场交付 |
| 5. 跨入口场景与交付 | 统一场景协调及单点修改、关联影响检查、配置资产导出／导入与准确恢复 | 不从聊天摘要重建代码，各入口版本可独立固定及追溯 |
| 6. 商业授权与运维 | 项目／实例授权、权益／服务期／额度、密钥轮换、升级分发与监控 | 与业务用户 Key 和 Agent 身份分开建模；失败不影响既有本地正式业务 |

上述阶段是后续规划，不因有 Task、Wiki 或需求案例就视为已实现。未知合同、字段和动作先完成固定模块、测试及审阅，再增加 AI 能力。客户专属功能放独立 `blue_project_*` 模块，共性修复回归标准模块。

## 不变约定

1. 系统准入、数量、公司权限、原生优先级、设备授权和状态机由固定服务复核；代码只补充合同允许的能力。
2. 云端维护批准规范与案例，资产及正式执行留在本地。聊天工具输出用于回放，不能充当权威示例库或故障兜底。
3. Wiki ready、知识批准、草稿验证和策略发布分别管理；旧单据固定版本，回滚不撤销已经发生的库存移动。
4. 每用户保留自己的业务 Key／Agent；同一项目团队共用五个业务 Task 和一个日常任务，新增用户只关联既有 Task，不按用户复制，也不拆成五套团队或人格。跨客户隔离使用团队／ACL 等真正权限边界。
5. 公开 AGPL／LGPL 来源、原作者、许可和补丁记录保留；运行秘密、客户数据和备份不进入 Git。

未选择的库存／包裹／盘点迁移见[候选清单](bluewms20-migration-selection.md)。每轮按明确业务需求确定范围，不自动安装所有候选。开发与合并遵循[开发规则](bluewms-development.md)。
