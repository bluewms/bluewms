# WCS 基础创建与 AI创建配置

不绑定AI时, 当前单据每条正数量、就绪移动行直接按行原位置到行目的位置创建一张goods任务, 使用人工选择的WCS入出方向、设备类别、设备及任务类型。无需AI服务或发布配置。自动触发、自动验证及验证前必须有WCS仍由人工开关控制。

`wcs_creation/4` 从全部有效行开始, lines阶段逐行返回create/wait/exclude、数量依据/数量、分组与位置来源和原因; tasks阶段再编排最多四个设备程序。支持同数据双/多任务: 同一计划的货物、设备、起终点相同, 每步独立身份, 后续goods等上一goods完成才发送。计划货物数量保存一次, 最终库存只验证一次。重复点击/扫描/并发不会重建同一组。

行确认、同载具全部确认、整单全部确认及装载阈值分开表达。提供原生同UoM数量、产品重量/体积及完整性、包装类型max_weight数据, 可用明确阈值编写策略; 不将all_picked当作满载。整载具实际货物完整、库存/预留/公司/冻结及在途覆盖由固定服务检查, 发送前再次检查。

支持行级/单据级物理点位与交接映射, 保存来源和原库存指纹, 不擅自改写库存位置。单据库区须包含既定库存位置且设备支持范围语义。无容器simulation支持, JSON需人工确认散件能力, HIK/WES仍需载具; 真实设备同数据多程序需现场确认能力。WES仅支持既定库存端点。详见能力与限制文档, 不宣称已完成真实设备联网验收。

生产只安装无示例代码、测试或需求正文的基础WCS接口定义。18个历史出厂定义归档，未修改的出厂正文按摘要清理，客户草稿、不可变版本、发布和执行历史保留。十组/4示例及25个精确用例位于Wiki分篇文档，回归夹具仅在tests/加载。

MuK与上架共用浮窗，按hook进入“WCS生成策略”Task。读取绑定资产和完整合同后，必须实际取得同项目Skill批准的01/06/07及真实Wiki来源，才能提交和验证AI草稿；无本地或上架示例兜底。AI没有发布或设备工具。客户端已接入，云端正文由用户最后写入批准，当前缺失时明确报错。

/1-/3历史与解释器保留, 不自动发布/改绑。/1以符合人工设备/模式/位置范围的原线路候选执行原代码; /2兼容原设置和人工授权; /3保持原合同。完整新能力使用独立/4模板。已固定单据、计划与报文不因发布/回滚改写。
