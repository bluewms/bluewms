# WCS 创建配置

沿用 ZF 原作业类型的 WCS 页签: 设备类别、设备、任务类型、生成条件、单双作业、按容器生成、自动创建和完成后验证. 这些字段提供默认行为, 可选的创建配置补充或修改条件、设备、起点、目的点及前后任务关系. 没有创建配置时直接使用原字段默认值, 无需维护独立线路.

入库以实际确认数量创建; 出库/内部搬运可使用有效预留数量, 不必先完成库存作业. 标准服务始终检查数量、库存预留、公司、批次、冻结和载具完整性. 勾选按容器生成时合并同一最外层容器的商品明细; 未勾选按明细准备搬运单元. 同一物理载具不能由多个在途计划重复搬运, 多商品整容器应勾选按容器生成.

`wcs_creation/2` 输入 `request` 和由原字段生成的默认任务 `candidates`. 配置输出 `result` 任务列表, 每项为 `equipment_id`、`location_res_id`、`location_dest_id`、`role`、`task_type`、`dependency_step`、`dependency_event`、`dependency_point` 和 `reason`. 所选位置/设备必须在输入允许范围内, 最多四张任务. 同货接力起终点连续, 后段等待前段完成. 空载具配合可使用原 point/take 触发并在前段完成时兜底释放.

三个示例: 沿用原默认规则、全部确认后创建、同货两段搬运. 两段示例的交接位置和任务模板必须按现场修改并试算. 样例 JSON 使用 name/input/expected_tasks, 精确比较任务列表. 草稿、验证、发布、回滚与上架创建配置共用资产流程. 真实作业试算只读, 不创建任务或固定版本. AI 聊天/Tencent 尚未连接, 当前可人工编辑相同草稿.

第一次实际生成任务时固定正式配置版本; 已保存计划和报文不会因改版变化. 定时创建、独立发送、完成后验证分开运行, 每次扫描/发送最多20项. 自动创建和自动验证默认关闭. 验证前必须存在 WCS 作业的原开关默认关闭; 已有任务必须全部完成, 需要 WCS 的数量必须完整覆盖.

旧 `wcs_creation/1` 发布版本及线路资料保留作历史, 不再用于新任务创建. 升级只准备新版草稿, 不自动发布. 用户需要重新试算、验证、发布后才能启用原绑定配置.
